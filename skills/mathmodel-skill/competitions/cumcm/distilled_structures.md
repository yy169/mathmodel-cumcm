## 0. 总体写作骨架

**法定骨架（唯一，来自 `paper_writing.md`）：**

```text
摘要
一、问题重述          1.1 问题背景 / 1.2 问题重述
二、问题分析
三、模型假设
四、符号说明
五、问题一的模型建立与求解    模型检验作为其下小节写在这里
六、问题二的模型建立与求解
七、问题三的模型建立与求解    （问题数更多时依次顺延）
八、模型的评价与推广          优点 / 缺点 / 推广（按需）
九、参考文献
附录
```

- **问题重述与问题分析相邻**：读者靠这两章合起来建立对任务的整体印象，中间插入假设与符号会打断这个过程；假设与符号则紧贴真正用到它们的建模章。
- **建模与求解按问拆成独立一级章节**，一问一章；后续章节序号随问题数顺延。
- **没有独立的“验证与稳健性”一级章**；检验写进该问的建模章当小节，或不写。
- **参考文献与附录是两个独立部分**，不合并成一章。
- 两种已废止的旧骨架，**不要再照它们搭目录**：一是把假设与符号排在问题分析之前（`重述 → 假设 → 符号 → 分析`）；二是把各问压进单独一章 `五、模型的建立与求解`，而不是按问拆章。另外也不再单列 `验证与稳健性` 一级章。
- 真正拉开差距的不是“有没有章节”, 而是每章内部是否保持“定义问题 → 建立数学对象 → 给出结果 → 回到题意解释”的闭环。
- 下面的每一节都按 `子章节切分 → 段落顺序 → 典型长度 → 反模式自检` 来写。

## 1. 摘要

| 统计项 | p25 / p50 / p75 |
|---|---|
| 摘要中文字数 | 748 / 992 / 1146 |
| 全文中文字符 | 15081 / 19835 / 24836 |
| 5 类摘要功能锚点命中 | 2 / 3 / 4 |

- **信息功能**: 问题与任务、方法、主要结果、验证与边界，以及确有证据的贡献或适用范围。不是每篇论文都需要五项，也不要求一项对应一段。
- **组织顺序**: 先让读者知道解决了什么，再说明怎么做、得到什么以及结论在何种条件下成立；可按子问题数量和当届版面合并或拆分。
- **典型分布**: 59 份可提取样本中，摘要字数中位数为 992，p75 为 1146。该观察只用于发现明显异常；段落数和长度仍应由题目、结果密度与当年格式决定。
- **反模式自检**: 1) 只有背景没有结果; 2) 结果有数值但没有任务对应; 3) 声称“提出/创新”却没有正文证据; 4) 结论依赖不确定参数却没有验证; 5) 关键词只列方法不列问题域。

## 2. 问题重述

- **子章节切分（法定）**: 只有 `1.1 问题背景` 与 `1.2 问题重述` 两节，不再拆出“题目任务”“研究目标归纳”等小节。
- **段落顺序**: 1.1 用 1 段概括场景与核心问题；1.2 先 1 段讲研究对象与必需条件，再逐问各 1 段，**“问题一：”“问题二：”等行内标签加粗**；子问题数量以题目为准。
- **写作提示**: 这一节只承担“对齐题意”，不承担“证明模型”；长短由题目复杂度决定，但任务与后文章节必须一一对应。
- **反模式自检**: 1) 直接复制题面原文; 2) 只写背景不写任务; 3) 子问题列表与后文章节不一致; 4) 没有给出“本文将如何处理”的过渡句。

## 3. 问题分析

- **子章节切分（法定）**: 直接进入 `2.1 问题一的分析` → `2.2 问题二的分析` → …。**不设“总体分析”小节**；确有必须说明的统一关系时，只在 2.1 前写 1 段 3～5 行总述。**不设“方法路线与依赖链”小节，技术路线图不放本章。**
- **段落顺序**: 每问 1 段（复杂时最多 2 段），只回答“难点在哪里 + 准备怎样解决”；不放公式、结果数字、结果图。
- **典型分布**: 样本的主章节数中位数为 5, 子章节数中位数为 28；这些解析值可能受 PDF 标题识别影响，只用于提醒把分析拆成可见的任务链。
- **反模式自检**: 1) 每个小问都写成同一种套话; 2) 没有说明为什么选择该模型; 3) 没写问题之间的依赖关系; 4) 只说“较为复杂”但不说复杂在哪里。

## 4. 模型假设与符号说明

- **子章节切分（法定）**: 假设与符号是**两个独立一级章**——`三、模型假设` 和 `四、符号说明`，都排在 `二、问题分析` 之后、各问建模章之前。不设“假设原则”“假设支撑”小节。
- **段落顺序**: 模型假设直接编号逐条列出，**每条一句话、以 5～7 条为宜，上限 10 条**；假设的依据、影响和敏感性结果不在本章展开，放到对应的模型建立或该问建模章内的模型检验小节处。符号说明用紧凑表格，只列高频、跨章节、易歧义的符号，表后注明“其余局部符号在文中首次出现处说明”。
- **写作提示**: 假设数量由问题需要决定，但超过 10 条要先合并同类项。符号定义与单位必须覆盖正文实际使用项。
- **反模式自检**: 1) 假设互相打架; 2) 假设没有依据; 3) 符号复用; 4) 单位缺失; 5) 首次出现术语无中英对照。

## 5. 模型建立与求解

| 统计项 | p25 / p50 / p75 |
|---|---|
| 主章节数 | 2 / 5 / 8 |
| 子章节数 | 20 / 28 / 40 |
| 公式数 | 12 / 24 / 67 |
| 图数 | 5 / 8 / 20 |
| 表数 | 4 / 6 / 9 |

- **子章节切分**: 每问一个一级章（五、六、七……），其下用二级标题拆环节，如 `5.1 建模准备` / `5.2 模型建立` / `5.3 求解算法` / `5.4 求解结果及分析` / `5.5 模型检验`；名称与数量由该问逻辑决定。
- **段落顺序**: 每个子问题可采用 `建模引入段 → 决策变量段 → 目标函数段 → 约束条件段 → 模型组装段 → 求解算法段 → 结果与解释段`，并按题型删改。
- **实测含义**: 公式识别数中位数 24, p75 为 67；题型与 PDF 解析差异很大，合理结论是“关键位置给出完整数学定义，其余用自然语言解释”，而不是追求公式数量。
- **反模式自检**: 1) 只有公式没有文字; 2) 目标函数与约束不闭合; 3) 变量定义晚于公式; 4) 求解方法与问题规模不匹配; 5) 结果没有回到题意解释。

### 5.x 通用模板
- 先写“本节针对<子问题>建立<命名变体>模型”。
- 再写“设<变量>、<参数>、<状态量>分别表示...”。
- 然后写“目标函数为...; 约束条件为...; 由此得到...”。
- 最后写“采用<算法>求解, 并在<图表>中给出结果”。

## 6. 灵敏度分析与稳健性检验（写在第五章内，不是独立一级章）

> **位置**: 作为该问建模章内的 `模型检验` 小节，紧跟这一问的求解；多问共用同一基础模型时只写一次，其余问不重复。确无必要时可不写。**不得单列为“模型的检验与稳健性分析”一级章。**
> **篇幅**: 小节就要有小节的体量，原则上半页以内——一段做法 + 至多一图一表 + 一句结论。**降级不是原样搬家**，整章塞进小节是错的。
> **压缩过程，不压缩证据**: 结论句与最关键的那张图表留正文；判据清单、逐例对拍明细、完整扰动矩阵移入附录并注明出处。直接支撑主结论的对比性检验优先留正文，纯自洽性检验优先进附录。

- **子章节切分**: 参数或数据不确定性 → 验证方法 → 结果 → 适用范围与失效条件。可按风险选择单因素、联合扰动、交叉验证、残差诊断或情景分析。
- **段落顺序**: 先说明不确定性来源与范围依据，再说明验证方法，用适合的图表或指标报告结果，最后解释结论何时成立、何时失效。
- **写作提示**: 摘要结构锚点的中位命中数为 3。验证部分应尽量量化误差、稳定范围或失效条件，但方法要和模型风险匹配。
- **反模式自检**: 1) 忽略可能的参数交互; 2) 只有口头稳健; 3) 没有给可核验范围或误差; 4) 没有说明验证方法; 5) 没有把扰动和实际含义对应起来。

## 7. 模型评价与推广

- **子章节切分（法定）**: `模型的优点` → `模型的缺点` → `模型的推广（按需）`（章号随问题数顺延）。**不单列“改进方向”小节**——真实发生的模型改进写在对应问题的建模章里；没有真改进不得虚构。**全章不超过一页，每条 1～2 句。**
- **段落顺序**: 优缺点各 1～3 条，有多少写多少不凑数；优点先给证据，缺点写清真实限制，推广仅在存在共同机制时给适配方式，并说明代价与边界。
- **提取观察**: `模型的优点` 命中 28 份、`模型的缺点` 命中 20 份、`模型的推广` 命中 9 份。关键词匹配不能推断奖项，只提醒评价部分要写具体证据、边界与代价。
- **反模式自检**: 1) 优点空泛; 2) 缺点只写“考虑不周”; 3) 推广没有适配步骤; 4) 没写代价; 5) 把万能模板当结论。

## 8. 参考文献与附录（两个独立部分，不合并成一章）

> `参考文献` 是一级章（章号随问题数顺延）；`附录` 是章后的独立部分，不编入章号。

- **子章节切分**: 参考文献单列；附录按 `附录 A 文件列表（文件名+功能，两列）→ 附录 B 程序代码（按问合并成一问一文件）` 组织，求解结果与坐标清单做成随附 xlsx，不排进版面。
- **段落顺序**: 参考文献按当届要求统一编排（仓库默认建议 GB/T 7714）；附录先给“对应正文哪一节”，再给代码或推导，不要把原始调试代码一股脑贴上去。
- **提取限制**: 脚本统计的是正文中形如 `[数字]` 的引用标记，可能重复计数，不能当作参考文献条目数。参考文献没有固定最低条数，应以正文实际使用、来源可靠和一一对应为准。
- **反模式自检**: 1) 附录代码无说明; 2) 参考文献格式混乱; 3) 中英混排无统一风格; 4) 附录中混入无关日志; 5) 文献列表与正文引用不对应。

## 10. 直接给 Claude 的结构提示

- 先定 `章节顺序`, 再定每章要回答的问题，最后定每段要输出什么信息；不设固定段数。
- 在发生输入、方法或结论切换时写清过渡，不要求每个章节机械配齐开头句、过渡句和结尾句。
- 子问题章节写法要可复用, 不能每问完全换风格。
- 结构模板的目标不是抄句子，而是先把问题、方法、结果与证据组织成可检查的推理链。

- 常见漏写: 只写标题不写承上启下, 或只给数学式不解释为什么这么写。

## 12. 分布数据的写作解释

- `摘要中文字数 748 / 992 / 1146` 只描述可提取样本的字符分布，可用于发现明显异常；摘要应是覆盖核心任务、方法、结果与边界的压缩叙事，不要求固定五段。
- `主章节数 2 / 5 / 8` 是解析器观察值，不是章节配额；应把总论、建模、求解、评价拆清楚，但不要为凑数乱分。
- `子章节数 20 / 28 / 40` 是解析器观察值；可把每个小问拆成可检验段落，让目录显示逻辑链，但无需追求固定段数。
- `公式数 12 / 24 / 67` 的含义是: 公式数量是服务于推导和约束, 不是为了“堆数学感”。
- `数字引用标记 16 / 28 / 63` 可能包含正文重复引用，只能用于粗略异常检测；文献的价值在于支撑模型选择、假设和方法，而非数量。

## 13. 结构自检

- 目录是不是 §0 的法定骨架：重述 → 分析 → 假设 → 符号 → 各问建模求解 → 评价推广 → 参考文献 → 附录，**建模与求解已按问拆章，且没有多出“检验与稳健性”一级章**。
- 目录能不能让人一眼看出“问题 → 模型 → 求解 → 验证 → 评价”的链条。
- 每个小问是否都有自己的开头、主体和结尾, 而不是平铺直叙。
- 若后续问题依赖上游结论，是否显式写明来源、版本、单位与误差传播。
- 检验小节和评价章是否只是短句堆砌, 还是有明确数据、边界和代价。
- 检验小节是否控制在半页以内；过程明细是否已移入附录并在正文注明出处，而不是整章原样塞进小节。
- 压缩后**结论、方法名和关键对比数据是否仍在正文**，没有把证据一起删掉。
