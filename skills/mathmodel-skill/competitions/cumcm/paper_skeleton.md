# CUMCM 论文骨架（Markdown 中间产物）

> 本文件只给内容占位符与章节顺序。**写作、排版、图表、公式、加粗、附录等所有硬规则以同目录 `paper_writing.md` 为准**；本文件不重复那些规则，冲突时以 `paper_writing.md` 为准。
> 开始写作前先检查同目录 `current_rules.md`；详细工作流见 `../../references/stage_08_writing.md`。
>
> **标题只写文字，不手写序号。** 章节、公式、图、表编号一律交给排版系统自动生成。下面骨架里的 `1.1`、`5.1` 等只标示层级，落到实际 Markdown 标题时**一个数字都不要写**（写成 `# 问题重述`、`## 问题背景`），否则会与自动编号叠加成 `2 二、问题分析`、`2.1 2.1 问题一`。

## 提交边界

当前规则基线要求电子论文第一页为摘要页、不放目录、不包含承诺书或编号页、不暴露身份，正文不超过 30 页。页数、文件大小、附录和 AI 使用材料以当年官方通知为准。

59 份可提取样本的观察值见同目录 `empirical.json` 与 `empirical_notes.md`。来源清单共 91 份；不要把样本分位数当成官方阈值。

## 内容骨架

> 下面标题一律不带数字（`# 问题重述` 而非 `# 1. 问题重述`），序号由排版系统自动加。
> 章节顺序固定为：问题重述 → 问题分析 → 模型假设 → 符号说明 → 各问的模型建立与求解（一问一章）→ 模型的评价与推广 → 参考文献 → 附录。重述与分析相邻，读者靠这两章合起来建立对任务的整体印象；假设与符号紧贴真正用到它们的建模章。
> **没有"模型的检验与稳健性分析"这一级章**：检验写在该问的建模章内当小节，或不写。

```markdown
# 摘要

<背景与本文总体任务；逐问以"针对问题X"起，点名模型/方法/关键结果；不放公式图表>

关键词：<问题域关键词；模型/算法关键词>

# 问题重述

## 问题背景
<1 段，用自己的话概括场景与核心问题，不复制题面，不提前出现模型/结果>

## 问题重述
<先 1 段讲研究对象与必需条件；再逐问一段，"问题一："等标签加粗>

# 问题分析

<优先直接进入"问题一的分析"；如需总述只写 1 段 3～5 行。每问 1 段讲"难在哪、怎么解"，不放公式/结果/技术路线图>

## 问题一的分析
## 问题二的分析
## 后续问题的分析

# 模型假设

<每条一句话，以 5～7 条为宜、上限 10 条；依据与影响放对应建模章。见 ../../templates/shared/assumption_table.md>

# 符号说明

<只列高频、跨章节、易歧义的符号；三列：符号 / 说明 / 单位（备注），无量纲写 `/`。
 排版目标是表格单独占一页，为此表前后的文字说明可有可无。
 见 ../../templates/shared/notation_table.md>

# 问题一的模型建立与求解

<建模与求解按问拆成独立一级章节，一问一章，后续章节序号顺延。
 技术路线图/流程图若确有必要，放在本章对应小节内，不放问题分析。
 建模章按题型选结构，不强套模板，规则见 paper_writing.md 第 8 节>

## 建模准备
## 模型的建立
## 模型的求解
## 求解结果与结果分析
## 模型的检验
<正确性检验、独立交叉校核、灵敏度与稳健性写在这里当小节，不单列一级章。
 多问共用同一基础模型时，只在其中一问下写一个统一的检验小节，其余问不重复。
 见 ../../templates/shared/sensitivity_table.md>

# 问题二的模型建立与求解

# 问题三的模型建立与求解

<各章结构同问题一；若依赖前一问，标明结果版本、单位和转换。
 按实际题目增减，不强行固定为三问>

# 模型的评价与推广

## 模型的优点
## 模型的缺点
## 模型的推广（按需，无实质内容则不写）

# 参考文献

<5～8 篇，由 refs.bib 经 BibTeX 生成，正文用 \upcite{} 上标引用；只列正文实际引用的来源>

# 附录

<附录 A 文件列表：两列表格（文件名 / 功能描述）
 附录 B 程序代码：按问合并成 q1.py~q4.py，一问一文件，问题切换处换页
 求解结果与坐标清单做成随附 xlsx，不排进版面；清除本机绝对路径与身份信息>
```
