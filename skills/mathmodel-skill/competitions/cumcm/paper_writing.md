# 26math 论文写作模块

> **最高优先级：禁止抄袭。**
>
> 任何优秀论文、参考文献、往届论文和网络资料只能用于理解题意、学习方法和核对格式，**不得直接复制、拼接原句、段落、摘要、问题分析、图表说明或推导文字**。
> 论文必须根据本题数据、模型、程序和结果独立组织语言。
> **禁止为了"像优秀论文"而复刻优秀论文的文字；只学习其结构、表达密度和排版习惯。**
>
> **题面原文同样不得照抄。** 问题背景与问题重述必须用自己的话重新组织，只保留理解题目所必需的条件、数值与交付要求；照搬题面段落、把题目要求逐句复述一遍，与抄袭优秀论文同等对待。判断标准：把本文的问题重述与题面并排，**不应出现成句雷同**。
>
> **信息密度按位置分配。** 正文只保留"理解模型、复现求解、支撑结论"所必需的信息；次要推导、程序实现细节和不支撑核心结论的中间数据应压缩或移至附录。
>
> **精简的是冗余，不是证据链。** 任何直接支撑模型合理性、求解可复现性或结果可信度的内容，不得因追求简洁而删除。准备删减某段内容、公式或数据前，应确认删后读者仍能回答三个问题：**为什么这样建模、结果怎样求出、结果为什么可信**；任一项无法回答，就应保留。
>
> **页数不是目标。** 除当届官方规定的页数上限外，本规范不设任何篇幅指标：不规定论文该多少页、正文该多长、每章该占多少。**不得为了缩短页数删除证据，也不得为了显得充实增加内容。** 页数是写完之后的结果，不是写作时要优化的目标；本规范中出现的"半页以内""不超过 10 条"等只约束特定局部，不构成全文篇幅要求。

---

## 本规范怎么用：三档效力

**本规范整体是重要参考，不是不可违逆的法条。** 但三档效力不同，不要一律当成建议，也不要一律当成死规定。

| 档位 | 含义 | 怎么处理 |
|---|---|---|
| **A 硬规则** | 违反了就是错，与题目无关 | 必须执行，不需询问，也不允许"这题特殊"绕过 |
| **B 默认做法** | 绝大多数题目适用的稳妥选择 | 默认照做；题目逻辑确实要求不同做法时**可以改**，但要清楚为什么改，并保持全文一致 |
| **C 参考** | 句式、模板卡、统计观察、示例 | 自由取舍，按题重写，不必照抄 |

**A 档硬规则只有这些（其余全是 B 或 C）：**

1. 当届官方要求（页数、匿名、文件大小、交付物）——官方 > 本规范。
2. 禁止抄袭：不复制优秀论文或文献原句；引用他人方法、公式、数据须规范标注；**严禁虚构文献著录信息**。
3. 标题不手写序号，编号交给排版系统；成品不得出现 `2 二、问题分析`、`2.1 2.1 问题一` 这类重复编号。
4. 图题在图下、表题在表上；格式 `图 1　标题` / `表 1　标题`，**不用英文冒号**；全文编号连续、正文引用与实际编号一致。
5. 表题与表体不得分离；长表跨页必须重复表头；**表格一律三线表，禁止竖线**。
6. 正文与摘要首行缩进 2 字，用排版属性实现，不敲空格。
7. 摘要不放公式、图、表、参考文献。
8. 数据、结果、结论必须与实际计算一致，不得为了行文顺畅改数字。
9. 定稿必须逐页看**渲染页面**判断版式，不能只看源码或文本提取。
10. **附录代码必须能跑出论文里的数。** **每问收尾当场实跑核对**，不留到结题前；跑不完或对不上的，**在对话里当面向作者说清是哪几问**（见 §20）。
11. **参考文献由 `.bib` + BibTeX 生成**，正文用 `\upcite{}`，不手写条目与上标编号（见 §16）。
12. **算不出结果的，在对话里说，不写进论文。** 正文不得出现「本题未能求解」「受算力限制未得到结果」「该问结果待补」这类自陈。凡是出不了结果、结果对不上、验证没做完的情况，一律当面告诉作者，由作者决定怎么处理；论文只呈现最终确定的方案与结果。

**B 档的典型例子**（可按题调整，不是禁令）：章节顺序与命名、模型检验放对应问题章内当小节、假设 5～7 条、每问一个自然段、摘要控制在一页、检验小节半页以内、评价章写优缺点、附录超过正文一半要自查。

> 偏离 B 档时的唯一要求：**是因为这道题的逻辑需要，而不是因为忘了或图省事**；一旦决定偏离，全文保持同一套做法，不要一半新一半旧。

## 0. 读取规则

本模块**每个论文写作任务只需读取一次**，读取后在当前任务中持续生效。

不要在"搭框架、写摘要、写正文、画图"每一步重复读取本文件。仅在以下情况重新读取：

1. 新开会话或新建独立写作任务；
2. 上下文压缩后已无法可靠记住本模块；
3. 本模块内容被修改；
4. 独立子代理需要自行撰写论文且没有继承这些规则。

目标是让规则长期生效，而不是反复消耗上下文。

## 1. 开工前

正式写论文前先完成四件事：

1. **读取当届官方格式要求**：页数、匿名、字体、文件大小、附件、代码、结果文件等；官方要求优先。
2. **先分析文献再定技术路线**，不得跳过文献直接建模。
3. **锁定排版模板**：自动编号、段首缩进、图题表题、三线表、公式编号、页码和交叉引用。
4. **建立论文骨架**，再开始填内容。

推荐骨架：

```text
摘要
一、问题重述
二、问题分析
三、模型假设
四、符号说明
五、问题一的模型建立与求解
六、问题二的模型建立与求解
七、问题三的模型建立与求解
（问题数更多时依次顺延）
八、模型的评价与推广
九、参考文献
附录
```

**重述与分析相邻**，合计一页半左右；假设与符号紧贴用到它们的建模章，也避免符号表夹在两个短章之间留白。

**建模与求解按问拆成独立一级章节**，一问一章；压进同一章当二级标题会让每问只剩三级标题可用，环节铺不开。后续章节序号随问题数顺延。

正文应形成清晰的建模闭环：**模型准备 → 模型建立 → 模型求解 → 结果分析 → 必要的模型检验/改进 → 模型评价**。其中各环节必须在需要时体现，但**不得为了形式完整机械设置同名小节或虚构不存在的“模型改进”**。

---

## 2. 摘要

**摘要不引用图表编号。** 摘要须能脱离正文独立阅读，出现「详见表 N」会把读者甩回正文；放不下的结果应压缩成结论句，而不是转成一个表号。

摘要原则上**独占第一页并控制在一页内**。若超页，优先删背景、次要技术细节和次要结果，禁止通过缩小字体或破坏模板强行塞入。

默认结构：

```text
第1段：研究背景 + 本文总体任务
之后：每个问题各1段
最后：关键词
```

硬规则：

- 摘要正文首行缩进两个汉字。
- 每问原则上以 **"针对问题一，/二，/三，/……，"** 开头。
- 摘要只允许三类内容加粗：
  1. **针对问题X，**(中文逗号也要加粗)
  2. **核心模型/核心方法名**
  3. **最终关键结果数字**
- 其余解释性文字不加粗。
- 每问必须说明：**模型/方法 → 求解思路 → 关键结果**。
- **每问以"本文建立了××模型"起头，先亮模型再展开方法**，不要先铺陈方法最后才点出模型名。
- **方法步骤给出显式路标**：多步求解用"首先…接着…然后…最后"串起来，让读者一眼看出这一问分几步走，而不是靠分号和"据此"自行拼接。**但这些路标词本身不加粗**——加粗留给模型名、关键方法名（如「岭回归」「模拟退火」）和结果数字。路标是骨架，不是重点。
- **同一套路标词不要每问都用。** 问题一用了"首先…接着…最后"，问题二就换别的连接方式（按逻辑关系直接叙述、用"在此基础上""据此"承接、或按对象分述）。四段用同一副骨架，读起来像填空模板，反而显得机械。**路标是给复杂的多步求解用的**；步骤本来就少的那一问，直接顺着讲完即可，不必硬套。
- **每问按"针对什么问题 → 做了什么研究 → 建立什么模型 → 得出什么结论（精度如何）"的顺序链组织。** 这不是固定句式，是整体思路：读者读完一段应能回答这四问。缺了"结论及其精度"的段落等于没写完。
- **摘要不写方法学元话语。** 诸如"全文各问的核心数值均另用原理不同的第二套算法交叉校核""本文所有结果均经过独立验证"这类关于研究方式本身的表态，属于正文模型检验章的内容，摘要一个字都不要写。摘要只讲：这一问用什么模型、怎么求解、得到什么结果。
- **先有正文再写摘要。** 摘要是正文的浓缩，不是提纲。允许在措辞上略作强化，但**任何数字、结论、方法名都必须在正文中有对应出处**，不得出现正文没有的内容。
- **摘要放不下的结果给出去处**：写明"详见表 N""详见图 N"，把读者引向正文，不要把次要数字硬塞进摘要。
- **后一问若建立在前一问基础上或引用了前一问的结果，须在该问段落开头点明继承关系**，例如"在问题二所得布局上""沿用问题一的××模型"。这既交代了问题间的逻辑，也避免读者误以为各问互不相干。
- **四问段落之后直接接关键词。** 不得再写全文总结段、方法论说明段或"本文特点"段——那些内容属于正文，摘要写到最后一问为止。
- 不放公式、图、表、参考文献。
- 不单列"创新点""本文特点"。
- **摘要单独成页。**
- **是「关键词」不是「关键字」，词之间用分号隔开。**
- **论文标题里不出现任何标点符号。**

## 3. 一、问题重述

固定采用：

```text
一、问题重述
1.1 问题背景
1.2 问题重述
```

### 3.1 问题背景

只写 **1 个完整自然段、约 4～6 行**，概括研究背景、研究对象、现实意义和核心问题。

**必须换一种表述，不得照抄题面。** 题面怎么说不重要，重要的是用自己的话讲清"这是个什么场景、为什么值得研究"。写完把本段与题面并排读一遍，出现成句雷同就重写。

禁止写成文献综述，禁止提前出现模型、算法和结果。

### 3.2 问题重述

先用 **1 个自然段** 简要说明研究对象、系统/器件工作机制以及理解题目所必需的基本条件。

随后按实际问题数逐问重述：

**问题一：** 一个完整自然段，准确说明已知条件、固定条件和要求求解的内容。

**问题二：** 一个完整自然段，说明相较前一问新增或放开的变量、约束、目标与交付要求。

**问题三：** 同理，明确与前问的继承关系、新增变化和目标。

若有更多问题，继续采用同一格式。

硬规则：

- **"问题一：""问题二：""问题三："必须加粗。**
- 每问原则上只写一个自然段，**约 3～5 行**。
- 不设置 `1.2.1 问题一` 之类多余小标题。
- **不照抄题面**，但关键数值、边界条件与交付要求不能漏。只写「这一问给了什么、要交付什么」，题面的铺垫、举例、解释一律不进正文。
- 不写"我们采用某算法"。
- 不写结果。
- 不在这里分析为什么这样建模。
- **整章原则上控制在 1 页以内。** 重述是让阅卷者确认你读懂了题，不是复印题目。

---

## 4. 二、问题分析

"二、问题分析"之后**优先直接进入 2.1**。

若几问之间确有必须说明的统一关系，只允许写 **1 段、约 3～5 行** 的总述。

禁止在 2.1 前连续写两三段总体分析。

每问原则上写 **1 个完整自然段**，复杂时最多 2 段。

只回答：

> 这一问难在哪里？准备怎样解决？

**问题分析里不写公式**，公式属于建模章。

问题分析中原则上不放：

- 正式公式；
- 最终结果数字；
- 结果图；
- 方法论证明；
- 调试过程；
- 技术路线图/流程图。

**禁止设置"2.x 技术路线"。**

---

## 5. 三、模型假设

只写真正进入模型的假设。

- **每条一句话**，不展开论证；
- **以 5～7 条为宜，上限 10 条**；
- 条数偏多时优先**合并同类项**（同一对象的几条性质合成一条），而不是把它们挪进正文；
- 禁止为了显得完整而堆无关假设；
- 假设依据、影响和敏感性结果不在假设章节展开；需要说明时放到对应的模型建立、模型检验或稳健性分析位置。

---

## 6. 四、符号说明

优先采用紧凑表格，只列高频、跨章节和容易歧义的符号。不必收录所有临时变量。

表格三列即可：**符号 / 说明 / 单位（备注）**。第三列写实际量纲，如 `周`、`kW/m^2`；**无量纲或纯比例的量统一写 `/`**，不要留空、不要写"无"或"—"，也不要在这一列塞解释性文字——解释属于第二列。同一符号在全文只能有一个含义；若某个量存在两个口径（如求和口径与并集口径的占用率），必须分列两行、各给各的符号。

**这一章的排版目标是：表格单独占一页。** 为此，表格前后的文字说明可有可无——写一段说明收录了什么、哪些符号容易混淆当然好，但若加了它就使表格挤不下一页，直接不写。表格本身能自解释。

若符号数量确实多到一页装不下，见 §15「图表位置」用 `longtable` 跨页并重复表头。

---

## 7. 技术路线图 / 流程图

流程图**不是必需项**。

- 文字已经能讲清楚，就不画。
- 建模过程复杂、流程图能明显降低理解成本时才画。
- 不得放在"二、问题分析"。
- 若需要，可放在该问的建模与求解章内对应小节。
- 不强制生成"全文总技术路线图"。
- 只展示最终正式求解链路，不展示试错和废弃方案。

---

## 8. 建模与求解各章（五、六、七……）

**建模与求解按问拆章：一问一个一级章节**，命名为 `五、问题一的模型建立与求解`、`六、问题二的模型建立与求解`，依次顺延。不要把各问压进同一章当二级标题——那样每问只剩两三级标题可用，建模环节铺不开。

**各章不设统一写作模板。应根据题型和模型逻辑自由组织，但必须做到：模型定义清楚、变量和假设明确、求解过程可复现、结果与模型对应、层级不过深、无重复赘述。**

**正文组织应以结果为导向，但不能只堆结果。** 建模部分只保留理解模型和复现求解所必需的关系、公式与算法；求得关键结果后及时解释其含义。禁止把建模章写成连续公式、连续表格或大量中间数据的打印件。

### 层级要求

一级标题为该问的建模与求解章，其下用二级标题 `5.1`、`5.2`……拆分主要建模环节，环节内部再复杂时才用到三级标题。

- 二级标题的**名称、数量和顺序由该问实际逻辑决定**，不设固定模板。
- 可根据需要使用“建模准备”“数据预处理”“参数确定”“坐标系建立”“模型建立”“求解算法”“模型求解”“求解结果及分析”“模型检验”等名称，但**不要求每项都出现**。
- **建模准备在确有前置工作时必须体现，但不强制使用“建模准备”四个字作为标题。**
- 简单问题无需为了凑层级强行拆节；复杂问题必须拆清主要建模环节。
- **禁止一级标题之下直接连续堆公式和表格**；复杂问题应通过二级标题明确区分建模准备、模型建立、模型求解和结果分析等主要环节。
- 自动标题原则上最多三级；三级以下使用 `（1）`、`①`、`Step1` 等内部层次，避免出现 `5.1.1.1` 一类过深编号。

### 正文不是开发日志

竞赛论文正文写模型与结果，不写实现过程。以下一律不进正文：

- **运行耗时明细**（「全量重算 99 毫秒、十万次 5 分钟」）——性能剖析报告。确需说明可行性时一句带过。
- **自己踩的坑与早期版本的 bug**——软件工程复盘。**修好的 bug 不写**，除非该失败揭示了模型层面的结构性事实。
- **代码实现细节**：数据结构、缓存、并行方式、库版本。属附录。
- **负面方法学结论**（如「代理保真度不足」）——只说明自己某条路没走通，不写。正文只呈现最终采用的路线。

判定：读给只关心「模型是什么、结果多少、为什么可信」的评委听，他会问「说这个干嘛」就删。

### 存在性认证应当产出策略

判定"存在一套满足要求的策略"之后，若求解器本身已经逐状态挑出了那个动作，就应把它保存下来
并能回放，而不是只返回布尔值。原因有二：交付要求往往是"给出可执行方案"而不是"证明方案存在"；
且回放输出可以直接生成调度表，避免 S3 那种手工倒推。

```python
policy[state_key] = chosen_action        # 认证时顺手存
replay(policy, observed_path)            # 沿真实观测路径逐期读出动作
```

能构造的就不要只证明存在。

### 简化过程，突出结果

竞赛论文不是科研论文，评委默认推导正确，看的是模型设定与结果。教科书级推导不展开，直接给最终表达式；中间代数步骤合并。**砍的是人人都会的步骤，不是本文独有的贡献**——自行构造的关键关系式必须保留并说清来由。

### 篇幅是诊断信号，不是指标

本规范不规定每章该写多少页（见开头“页数不是目标”）。但**篇幅可以反过来当体检指标**：若某问的建模与求解**不足两页**，通常不是这一问简单，而是建模环节没交代全——多半缺了建模准备、求解算法或结果分析中的某一环。此时应回头检查是否漏写，**而不是加内容把页数填上去**。

### 多模型对比是加分项

同一问有多个可选模型时，**并列给出并用一张表比较精度、误差与适用性**，同时交代「为什么选这个」和「选错会差多少」。对比须同口径，表后写明选择依据。

以下仅作为不同题型的**逻辑参考，不是固定模板**：

### 计算 / 正演型
`模型建立 → 计算方法 → 算法步骤 → 求解结果 → 结果分析`

### 优化型
`决策变量 → 目标函数 → 约束条件 → 完整优化模型 → 求解算法 → 求解结果 → 结果分析`

### 预测 / 回归 / 统计型
`数据与变量处理 → 模型选择 → 参数估计/训练 → 误差检验 → 预测结果`

### 评价 / 决策型
`指标体系 → 数据预处理 → 权重/评价模型 → 综合得分或排序 → 稳健性分析`

### 机理 / 动力学型
`变量与关系 → 控制方程 → 初始/边界条件 → 求解方法 → 结果与机理解释`

以“让评委最快看懂”为准，不为模板完整制造无意义小节。

## 9. 避免重复

摘要、问题分析、模型建立可以谈同一条思路，但功能不同：

| 位置 | 重点 |
|---|---|
| 摘要 | 模型 + 方法 + 结果 |
| 问题分析 | 难点 + 准备怎样解决 |
| 模型建立 | 数学定义 + 模型 + 算法 |

**三处逻辑一致，但禁止逐字复制。**

## 10. 模型检验、稳健性与改进

**模型检验的位置只有两个选项，二选一，没有第三种：**

- **选项 A**：写在该问的建模与求解章里面，作为 `5.X 模型检验` / `5.X 敏感性分析` / `5.X 稳定性分析` 等二级小节。
- **选项 B**：确实没必要检验时，不写。

**默认不把"模型检验""敏感性分析""稳定性分析"写成一级章节**（B 档）。这样安排的理由是：检验是为某一问的模型服务的，紧跟该问更好读，单列一章容易写成与正文脱节的附加物。若某道题的检验确实是独立的研究内容、体量与地位都够一章（例如题目本身就要求做验证性研究），可以破例单列，但要清楚这是偏离默认做法。

默认的一级章节顺序，不管写不写检验都不变（问题数不同时序号顺延）：

```text
五、问题一的模型建立与求解
六、问题二的模型建立与求解
七、问题三的模型建立与求解
八、模型的评价与推广
九、参考文献
附录
```

### 篇幅：小节就要有小节的体量

**降级成小节，篇幅必须跟着降，不能把整章原样搬进来。** 一个三级小节写满两三页，那不是小节。

- 单个 `模型检验` 小节的正文**原则上控制在半页以内**：一段说明做法 + 至多一张图或一张表 + 一句结论。
- 优秀论文的典型体量：一段做法、一张图、一句结论，全节约 100 字。
- **压缩的是过程，不是证据。** 结论句与最关键的图表留正文；判据清单、逐例明细、完整扰动矩阵移入附录并注明出处。
- 判断标准：删掉后读者仍能答出**用什么方法验的、结果是什么、模型可不可靠**，就够了。

具体要求：

- 与某一问强相关的正确性检验、独立对拍、误差分析、收敛性分析、灵敏度分析或稳健性分析，紧跟该问模型求解，设为 `5.X 模型检验` 等二级小节（编号随该问所在章与已有小节数确定，不固定）。
- 多个问题共用同一基础模型时，只在其中一问下面写一个 `模型检验` 小节，其余问题不再重复写。
- 直接支撑主结论的对比性检验（例如证明"方案二优于方案一"在多种假设下都成立）优先留在正文；纯自洽性检验（量纲、对称性、剪枝一致性等）优先进附录。
- 不要求每问都做检验，也不要求每问做同一种检验。
- 检验只做真正能支撑模型可靠性的内容，禁止为了形式完整重复画图、重复随机实验或重复写相同结论。
- **新增一项检验前先问它解决哪个真实争议。** 解决不了就不加——Bootstrap、AICc、留一、留二
  堆在一起并不比一条判别性证据更有说服力。
- **但"改正一处错误陈述"不算加方法，属于必做。** 二者的区别在于：前者是"再多证一点"，
  后者是"论文现在写着的话不成立"。实测教训：因样本无重复而声称"数据不足以估计方差、
  不给区间"——前半句对，后半句错，残差 Bootstrap 正是为无重复观测设计的。这种情况要么把
  区间做出来，要么把话改成不越界的表述，并同步下调该条 Claim 的证据等级。
- 若建模过程中确实发生模型修正、参数修正、约束补充或算法改进，应在对应问题中明确写出“原问题/不足 → 改进内容 → 改进后的影响”；**没有真实改进时不得为了凑结构虚构“模型改进”。**

## 11. 模型的评价与推广章

本章用于评价最终模型，应**简洁、直接、与正文模型对应**，禁止写成长篇总结。

原则上必须包含：

- `6.1 模型的优点`
- `6.2 模型的缺点`

若模型确有明确且合理的推广场景，可增加：

- `6.3 模型的推广（按需）`

写作要求：

- 优点、缺点一般各列 **1～3 条** 即可，有多少写多少，不凑数量。
- 每条尽量只说明一个具体特点，并与本文实际模型、算法、假设、误差或结果对应。
- 优点可从模型精度、解释性、求解效率、稳健性、可复现性、适用范围等真实表现中提炼，禁止使用无依据的万能套话。
- 缺点应指出真实局限，如假设理想化、离散误差、参数依赖、计算量、数据不足等；不得为了“显得客观”编造不存在的问题。
- 模型推广只在有明确对象、适用条件和调整方式时写；没有实质内容时不强制设置。
- **不强制单列“模型改进”小节。** 真正发生的模型改进应优先在该问的建模与求解章中呈现。

**全章不超过一页，每条 1～2 句。** 实测反例：优缺点各写几个大段，整章占满一页，读起来像又一篇小论文。

**禁止写成结果总结或技术复述**——重复一遍算出了多少、用了什么算法，那是把正文再讲一遍，不是评价。

**编号用 `1.` `2.` `3.`，不用 `（1）（2）（3）`。**

## 12. 结果分析

不要逐项复述表格。

推荐：

```text
（1）**核心结论。** 原因或机理解释……
（2）**核心结论。** 与基线/其他方案比较……
```

要求结论在前、解释在后；每条只讲一个主要发现。

**每一个图、每一个表的紧前或紧后都必须有描述性文字**，说明「给出什么、结果是什么、意味着什么」。任何图表都不允许孤零零插在两段之间。禁止「表 1 → 表 2 → 表 3」式的连续堆表。

**禁止几个字独占一段**，应并入相邻段落。例外：引出行间公式的短句（如「其中修正系数定义为」）与该公式构成整体。

总体原则：**公式少而关键，图表适量且有用，分析简短但有结论。**

## 13. 标题与编号

- 一级标题：中文序号，如 `五、问题一的模型建立与求解`；
- 二级、三级：阿拉伯数字点分，如 `5.1`、`5.1.1`；
- 自动标题最多三级；
- 更低层级使用 `（1）`、`①`、`●`、`Step1`；
- 图、表、公式、章节引用尽量自动编号与交叉引用。

禁止出现 `2 二、问题分析`、`2.1 2.1 问题一`。

### 数字写法（硬规则）

**一个完整数字内部禁止出现任何空格**（含 `\,`）：写 `12985074`，不得写 `12 985 074`。被空格切开的数字跨行时会断成两截。确需千分位分隔时只用逗号，全文统一。

## 15. 段落、公式、图、表

### 首行缩进
摘要和正文均首行缩进 **2 个汉字宽度**。不要用手敲空格或 Tab 模拟。

### 西文斜体与标点

- **正文中的西文一律斜体**：变量、算法名、人名（*Steiner*、*Dijkstra*、*Hanan*）、缩写。**百分号随之斜体，数字不斜体。**
- **正斜体要分清**：`sin`、`max`、`log`、微分符 `d`、单位一律**正体**；变量斜体；**矢量用黑体**。
- **除数学公式外，全部标点用中文全角**：逗号、句号、冒号、分号、括号。**双引号要输出成中文弯引号**，不能是 `"`。
- 图题、表题不用英文冒号。
- **正文与公式中出现的同一符号必须完全一致**，包括正斜体、上下标、字体。

### 公式后的段落不缩进

Pandoc 会在 `\end{equation}` 后留空行，TeX 因此判定新段落开始并首行缩进两字；但行间公式之后的文字通常是承接上文的同一句，缩进即断了语气。

```latex
\usepackage{noindentafter}
\NoIndentAfterEnv{equation}
\NoIndentAfterEnv{align}
```

### 列表环境

`\item` 内容较长换行时，**第二行起不缩进**，只第一行有缩进：

```latex
\begin{enumerate}[wide]
```

### 列表条目按自然段排

模型假设一类的编号列表，条目应与正文段落同形：**首行缩进两字，续行顶格**。`wide=0pt` 会让首行也顶格，整块看起来像代码；正确写法是 `wide=\parindent`（等价于 `leftmargin=0pt` + `labelindent=\parindent`）。

```latex
\setlist[enumerate]{wide=\parindent,itemsep=2pt,parsep=0pt,topsep=4pt}
```

### 加粗的分工
**加粗只在摘要里使用，正文除标题外一律不加粗，表内数字也不加粗。** 摘要靠加粗分层；正文已有标题、编号和段落结构承担这个作用，再加粗只会让页面花掉。

摘要中允许加粗的是：`针对问题X，`、核心模型与方法名、关键判断、最终结果数字。解释性文字不加粗。

**唯一例外是结构标签**：问题重述中的 `问题一：`、`问题二：` 仍须加粗，它们功能等同小标题。除此之外正文不得再有加粗。

### 公式
- 独立公式居中；
- **凡独立成行的公式一律编号**，采用「章-序」格式，如 `(5-1)`、`(5-2)`，编号右对齐；
- **反过来说，不值得编号的公式就不该独立成行**：若某式只是行文中的一处代换或一个简单定义，删掉编号后也没人会引用它，就把它并入正文写成行内公式，不要占一整行；
- 关键符号及时解释；
- 教科书级公式不做冗长推导，优先给最终表达式或规范引用；
- **公式取舍以"是否影响理解模型与结果"为准**：若删去某公式后，读者仍能完整理解模型结构、求解逻辑和结果来源，则该公式原则上不进入正文；
- **核心模型关系、目标函数、关键约束、自行构造的重要指标及直接支撑主要结论的关系式必须保留。**

### 图
- 图居中；
- 图题在图下；
- 格式：`图 1　图题`；
- **不用英文冒号 `:`；**
- 正式图必须被正文引用和解释；
- **图内文字（标题、坐标轴、图例、色标）在 A4 印张上须清晰可读**：正文缩放后字号不小于正文的七成，线宽与标记不因缩小而糊成一团；
- **必须是矢量图或高分辨率位图**：优先 `.pdf` / `.eps` / `.svg`，位图不低于 300 dpi。Python、MATLAB 出图直接导出 pdf，**禁止截图后粘贴**；
- **图内不要再写一遍图题。** 绘图工具默认加的标题与下方的「图 N　图题」重复，占掉版面还显得啰嗦。做法是**把图内标题删掉**；若它带了图题没有的信息，先分清那是标识还是结论：口径、单位、截断方式一类的**标识**可进图题括注，写成 `图 3　各行数六个独立种子的结果分布（色标按 97 分位截断）`；「组间差小于组内差」这类**结论**一律进正文，图题保持短标识，见下节；
- **`\includegraphics` 的宽度必须等于出图时的自然宽度。** 按 0.7 倍正文宽出的图若写成
  `width=\linewidth`，等于被放大 1.4 倍：图内字号随之变大、整幅高度也涨，页尾装不下就被
  整幅推走。实测教训：连续几轮「把图改小」都没效果，原因就是缩小的量被这道放大抵消了。
  出图后用 `fitz.open(pdf)[0].rect` 量一次自然宽高，据此写 `width=<w/正文宽>\linewidth`；
- **图太高装不下时，改版式而不是缩小**。4×1 竖排改 2×2 网格，高度可降四成而单个分面反而更大；
  单纯调小 `width` 会把图内字号压到正文的七成以下，违反上一条；
- **图不宜过多，需要才放**；
- 图表两侧尽量留白；
- **热力图不要按最大值归一化**：重尾数据下单个极值会把其余压到色标底端，整幅图发黑。按高分位（如 97 分位）截断或用对数色标，并在图题注明口径；
- 原则上一行最多两个主要子图。

### 图内只放事实，不下结论

**图题与图内文字都只作标识，判断句一律写进正文。** 图表是给评委核验的证据，不是下判决
的地方；把结论刻在证据上，读者无从区分哪些是量出来的、哪些是作者断言的。

三条判据，任一条不满足就把那句话搬回正文：

1. **本图有没有对应的量。** 曾在「切换次数上限—总等待时间」的权衡前沿图里给基准线标注
   「固定方案 15753（超容，不可行）」。该图纵轴是等待时间，图上既无排队人数也无容量线，
   「超容」在本图内无据可查——它的证据在队长时程图和逐时段表里。改为只标「固定方案 15753」。
2. **正文是不是已经说过。** 说过就是重复；没说过，说明结论被藏进了图里，正文缺了一句。
3. **限定条件跟不跟得过去。** 「不可行」是无条件断言，而可行性常依赖模型口径与参数范围。
   正文有上下文承载限定，图内文字没有；越短越硬的判词越不该进图。

**这不是禁止评价。** 判断句本身是交付物：题目问「是否存在安全风险」，答案只能是一个判断；
「模型的评价与推广」整章都是评价，含负面自评。区别只在两处——

- **位置**：评价写在正文、写在证据之后，不进图内、不进图题、不进表头。
- **对象**：评价研究对象（方案、模型、结果）要写；评价自己的工作过程（哪条路没走通、
  算力不够、代理保真度不足）不写，见 §19。

写进正文的评价，三样不能少：**证据在场、限定条件在场、用数字不用形容词。**
「进站峰值 296.4 人，距上限 3.6 人」合格；「安全裕度较为紧张」不合格——形容词替代了数字，
读者没法核。

### 图表位置

- 导言区设 `\floatplacement{figure}{H}` 与 `\floatplacement{table}{H}`，图表就地放置，「如图 N」不再与图隔页。
- **副作用**：`[H]` 装不下就整页推走，页尾留大片空白。**装不下的长表（如符号说明表）改用 `longtable`**——非浮动体，可跨页并自动重复表头。
- 不要用「放开浮动」解决空白：表浮到次页、正文回填本页，阅读顺序被打乱，比空白更糟。
- **要改就一次全改。** 逐张把 `table[H]` 改成 `longtable`，只会让页尾空白从这一页迁到下一页——
  被推走的换成了下一张表。确认版面有空白问题后，把正文里所有非浮动需求的表一次性改完。
- **正文不允许出现大片空白**，尤其图表处。

### 图内文字重叠

只能看渲染图发现，文本提取查不出。四类成因：

1. **子图标题过长**（把统计量写进了标题）→ 标题只留身份，统计量进正文。
2. **多子图各带色标** → 量纲一致时合用一个色标，只最左幅保留纵轴标签，加高。
3. **双轴标注被另一条线穿过**（`twinx` 恒绘于上层，白底衬也挡不住）→ 移到该线不经过的区域。
4. **图例压住数据点**（最隐蔽，曾致结论说反）→ 逐张查图例下方有无数据；坐标轴上限按实际画出的点自适应。

### 同一组数据只用图或只用表

**逐列比对判定，不凭印象**：

- 图的变量是表的列的子集且无独有信息 → 删图留表；
- 各有独有信息（图有分布形态/样本云，表有绝对值）→ 不算重复，都留；
- 两边各有对方没有的东西（表有均值和标准差，图有中位数和散点）→ 留一个，另一个的关键数写进正文。

### 图与表不得连续出现

两个浮动体之间必须有正文。图后紧跟结论句（见 §12），否则评委只能自己猜这张图想说什么。

### 表
- **一律用三线表：只有顶线、表头下的分隔线、底线三条横线，禁止任何竖线**，也不要给每行都加横线。需要分组时用留白或 `\cmidrule` 局部短线，不靠画格子；
- 表题在表上；
- 格式：`表 1　表题`；
- **不用英文冒号 `:`；**
- 表头带单位；
- 同列小数位统一；
- **表内数字不加粗**；需要指出最优值时用文字在表后说明，不靠字重；
- 结果表与最终交付文件逐位核对。

分页：
- 表题与表体不得分离；
- 短表必须整体同页；
- 长表跨页时**重复表头是硬要求**；
- "续表 N"是推荐增强项，可由 LaTeX 模板、Pandoc filter 或生成后的 `.tex` 实现。

如需防标题/短表孤立分页：

```latex
\usepackage{needspace}

\Needspace{18\baselineskip}
\subsection{...}
```

`\Needspace` 必须放在标题之前。

## 16. 参考文献与学术规范

**参考了什么就如实列什么。** 正文实际引用的文献必须在文后真实列出，正文未引用的文献不得为了数量加入。

- **禁止复制参考文献或优秀论文的原句。**
- 学习其方法时必须重新理解并独立表达。
- 使用他人的方法、公式、观点和非显然数据时规范引用。
- 默认采用顺序编码制，按正文首次引用顺序排列为 `[1]`、`[2]`、`[3]`……；若当届官方格式另有要求，以官方要求为准。
- 文献类型必须按真实来源标注，如期刊 `[J]`、学位论文 `[D]`、专著 `[M]` 等。
- 中文文献保留真实中文著录信息；英文文献保留真实英文作者、题名和来源信息，不自行翻译后冒充原始题名。
- **严禁虚构或补造作者、题名、期刊、学校、年份、卷期、页码、DOI 等信息。** 缺失的信息应先核实，无法核实则不得自行编造。
- 正文引用编号与文后编号必须一一对应，同一文献不得重复编号。
- 每条文献独立列出，编号左对齐，换行后的续行保持统一缩进和紧凑行距。

常见著录形式可参考：

```text
[1] 作者. 题名[J]. 期刊名, 年, 卷(期):页码.
[2] 作者. 题名[D]. 学校, 年.
[3] 作者. 书名[M]. 出版地:出版社, 年.
```

以上仅为格式示例，**不得把示例中的字段当作真实信息自动补全**。

### AI 工具不进参考文献编号

AI 辅助工具不是学术文献，不与标准、期刊论文并列编号。工具名称、模型版本、用途、
人工复核方式全部写在「AI 使用说明」一节与支撑材料里。除非当届官方明确要求按文献格式著录。

### 数量

**5～8 篇为宜。** 少于 5 篇显得没有查阅基础；多于 8 篇时往往混进了正文并未真正使用的条目。若确有超出，逐条检查正文是否真的引用过。

### 必须用 `.bib` + BibTeX，禁止手写条目

手写条目要人工维护编号，增删一条就得改正文所有上标。把文献写进 `refs.bib`（Google Scholar、百度学术、知网可直接导出），排版交给 BibTeX：

```latex
\bibliographystyle{gbt7714-numerical}   % 国标 GB/T 7714 数字顺序制
\bibliography{refs}
```

**正文引用用 `\upcite{}`，编号置于文字右上角**；`\cite{}` 出来是行内基线编号，不合国标顺序编码制惯例。若无 `gbt7714` 宏包，正文里自定义等效命令即可：

```latex
\newcommand{\upcite}[1]{\textsuperscript{\cite{#1}}}
```

**尽量不一次引多篇**，`[5,6]` 这类连引拆成两处单引。

**三个已验证的实现坑：**

1. **渲染脚本通常不跑 bibtex**，引用会停在未解析状态。渲染后补：拷 `refs.bib` 进输出目录 → `bibtex main` → 再跑两遍 xelatex。写成 `build.ps1` 封装。
2. **`gbt7714-numerical.bst` 产出 natbib 格式的 `\bibitem[Author(Year)]{key}`**。导言区不可达时，标准 `thebibliography` 会把可选参数当标签印成 `[Hanan(1966)]`。解法：编译后把 `.bbl` 里的 `\bibitem[...]` 剥成 `\bibitem`。
3. **`\setCJKmonofont` 等导言区专用命令在正文里报 `Can be used only in preamble`**。动手前先确认导言区能否改。

### 排版

- 序号**悬挂缩进**，续行与正文首字对齐；正文**左对齐不作两端拉伸**；**条目间留空约 6pt**。用 `list` 环境实现：

```latex
\begin{list}{}{%
  \setlength{\labelwidth}{2.4em}\setlength{\labelsep}{0.4em}%
  \setlength{\leftmargin}{2.8em}\setlength{\itemsep}{6pt}%
  \setlength{\parsep}{0pt}\setlength{\listparindent}{0pt}}
\raggedright
\item[{[1]}] ...
\end{list}
```

- **DOI 可不写**，国标未强制。
- **条目太多时文献表单独成页。**
- **问题背景或问题重述部分至少要有一篇参考文献。**

## 17. 附录

**附录用于补充和复核正文，不是正文的垃圾桶。** 正文必须独立说明核心模型、求解逻辑、主要结果和主要结论；任何直接影响主要结论理解与可信度的内容不得首次只出现在附录中。

- 当包含多个程序或数据文件时，优先在附录开头给出**文件名 + 功能**清单，便于定位和复核；行数、校验码等可作为可选增强项。
- 每段代码应明确标注**文件名及所属问题或功能**，禁止无标题地连续堆放源码。
- 代码完整程度按官方要求定：要求完整程序就完整附上；允许单独提交支撑材料时，附录保留核心程序即可。
- 正式附录代码应清理无关调试输出、废弃代码、大量注释掉的旧方案和本机绝对路径，但不得因追求整洁而删除复现所必需的内容。
- 长代码应使用统一、可读的代码环境，优先采用“**附录编号/文件名 + 有边界的代码区**”组织，保持区块边界清晰并支持自动换行，禁止按普通正文样式裸排大量源码。
- **附录以代码为主体，中文说明少而关键。** 禁止把正文分析搬进代码区，禁止为每行代码添加解释性中文注释。
- 注释优先只标记：程序/函数用途、关键参数、不直观的核心计算步骤和重要算法阶段；能从代码直接看懂的赋值、循环、绘图语句不额外解释。
- 注释原则上采用简短单行形式，**注释符按所用语言写**（Python 用 `#`，MATLAB 用 `%`），如 `# 目标函数`、`# 计算遮挡效率`、`# 生成可行解`；保持代码视觉主体清晰。
- **附录篇幅超过正文一半时自查**是否混入非核心脚本或重复代码；这是警戒线不是禁令，且不得为缩短篇幅删掉复现所需内容。

### 推荐结构：附录 A 文件列表 + 附录 B 程序代码，其余进附件

**附录里只排程序代码。** 求解结果、坐标清单做成随附 `.xlsx`，不排进版面——评委不会逐个核对几页坐标表，却实实在在占篇幅。

```
附录 A　文件列表        两列表格：文件名 / 功能描述
附录 B　程序代码        q1.py ~ q4.py，问题切换处换页
（随附）result1~4.xlsx  各问求解结果，一张结果表一个工作表
（随附）推荐布局坐标.xlsx
```

附录 A 的表就两列，不要展开成五列：

| 文件名 | 功能描述 |
|---|---|
| q1.py | 问题一程序代码 |
| result1.xlsx | 问题一求解结果 |

该表按**两列定宽、左对齐**排版，文件名用等宽体。用 `{ll}` 的自然宽度会把整表挤成窄条，与页面宽度不称；`>{\raggedright}p{0.40\linewidth}p{0.55\linewidth}` 一类的定宽写法可占满版心。

**所属问题、输入、输出写在代码开头的注释里**，不占表格宽度。

**附录与参考文献的标题不参与章号编号**。模板若已切到 `\appendix`，沿用 Markdown 的 `#`/`##` 会排成「A附录」「1.1」这种错号，改用 `\section*{附录}` / `\subsection*{附录 A\quad 文件列表}`。

### 按问合并成一问一文件

评委按问题读，不按你的工程结构读。**把分散的计算脚本按问合并成 `q1.py`～`q4.py`，一问一个文件。**

- **共用代码只在链首出现一次**，后续文件用 `from q1 import *` 取用。**绝不复制**：四份底座会让代码量翻倍、附录页数翻倍，且违反「重复函数不得用来凑篇幅」。
- **切分点要按真实调用关系定，不能按叙事直觉定。** 曾把「行布局构造」按叙事划给问题二，但问题一构造训练集时就要用它生成布局，结果 q1 出现 11 个未定义名字。**合并后必须做未定义名字检查**（见 §21）。
- 依赖链要最小：只加真正用到的。q3 若只用到已并入 q1 的函数，就不要让它依赖 q2。
- 合并脚本要可重跑，源码一改重新生成即可，避免附录与支撑材料漂移。

### 代码排版参数

| 项 | 取值 |
|---|---|
| 字号 | 10.5pt（清晰可读的下限附近；低于 9pt 不可接受） |
| 行距 | 实际约 15pt |
| 行号 | 左侧连续，8.5pt，灰色 `#808080`，与代码间隔约 10pt |
| 配色 | 关键字 `#1264C0`、注释 `#009900`、字符串 `#1E9E78`、正文黑 |
| 边框 | 左侧细黑线，不用四边重框 |
| 长行 | 版心内自动换行，续行加统一标记（如 `↪`），不得截断变量或字符串 |
| 引号 | `upquote=true`，保证引号、连字符是 ASCII 原字符，不被中文字体换成弯引号 |

**行距会被模板的中文行距倍数放大**（实测约 1.27 倍）。`\fontsize{10.5}{X}` 里的 `X` 要按「目标行距 ÷ 该倍数」给，否则实际行距会比预期大三分之一，页数凭空多出一截。

### 附录代码的三条硬要求

1. **只排代码，不写文件头说明块。** 文件的所属问题与功能由附录 A 交代，代码顶部再写一遍标题、输入、输出、依赖是重复。直接从 `import` 起排，每个 import 后跟一句用途即可。
2. **注释要少而关键。** 多行文档字符串压成一行，连续三行以上的整行注释块只留首行，行尾短注释保留。但这一步若由脚本按规则批量执行，**必须抽查结果**——规则删不出语法错误，却可能删掉理解算法所必需的说明。
3. **去掉本机绝对路径**，只留文件名。但**同时要在附录 A 或代码注释里说明「运行时需把附件数据文件放在代码同级目录」**，否则评委真去跑会卡在第一步。

## 18. 读取与检查节奏

**本模块每个论文任务只读取一次。**

不要在搭框架、写摘要、写正文、画图时重复读取。

正常写作即可。正文首次实际出现摘要、多级标题、公式、图、表后编译一次 PDF 做快速检查。

定稿后必须逐页查看**渲染出来的 PDF 页面**。排版、编号、间距、分页、图表位置等版式问题一律以最终渲染页面为准；源码和文本提取结果只能辅助检索，不能作为版式正确的最终判据。文本提取可能合并、忽略或重排视觉元素，从而漏掉重复编号、标题错位、孤儿行等仅在渲染页面中可见的问题。

## 19. 高风险错误

| 错误 | 典型表现 |
|---|---|
| 抄袭式写作 | 复用优秀论文原句/段落 |
| 照抄题面 | 问题背景或问题重述与题目成句雷同，把题目要求逐句复述一遍 |
| 摘要拖尾 | 四问段落之后又写总结段、方法论段或"本文特点"，没有直接接关键词 |
| 摘要技术细节过密 | 把误差量级、参数扫描、程序实现、次要假设塞进摘要 |
| 正文滥用加粗 | 除标题外正文仍有加粗，或表内数字加粗 |
| 数字被空格切开 | 写成 `12 985 074`、`12\,985\,074`，跨行时断成两截 |
| 行间公式无编号 | 独立成行却不编号；或反过来，把不值得编号的式子占一整行 |
| 图表无描述 | 图或表孤零零插在两段之间，前后都没有说明性文字 |
| 几个字独占一段 | 十来个字单独成段（引出行间公式的短句除外） |
| 热力图发黑 | 强度图按最大值归一化，单个极值把其余压到色标底端，看不出结构 |
| 结果表连堆无分析 | 连续多个表/图后只有数字，没有结论性分析 |
| 建模章层级混乱 | 复杂问题只有 `5.1/5.2`，没有拆清建模准备、模型建立、求解与结果分析 |
| 建模章过薄 | 某问的建模与求解不足两页，多半漏了建模准备、求解算法或结果分析 |
| 模型检验机械重复 | 每问强行重复同一种检验，只为凑结构 |
| 检验小节超重 | 由整章降级成小节后篇幅没压，一个三级小节占两三页，过程明细全堆在正文 |
| 模型评价空泛 | 优缺点写成“模型准确、模型简单、推广性强”等万能套话 |
| 参考文献失真 | 虚构或自动补造作者、卷期、页码、DOI 等著录信息 |
| 附录注释过密 | 逐行中文解释或把正文段落塞进代码区 |
| 重复编号 | `2.1 2.1`、`2 二、` |
| 摘要首段顶格 | 第一段没有两字缩进 |
| 问题分析过长 | 2.1 前先写两三段总结；或与问题重述合计超过一页半 |
| 技术路线错位 | 出现 `2.x 技术路线` |
| 机械重复 | 摘要/分析/建模逐字复制 |
| 表格孤儿行 | 最后一行单独跨页 |
| 图已过期 | 图仍展示旧模型/旧方案 |
| 附录淹没正文 | 大量源码占多数页 |
| 凭文本提取判断版式 | 仅用 pdftotext/复制文本检查编号、间距、分页等，漏掉仅在渲染页面可见的版式缺陷 |
| 代码跑不出论文的数 | 附录代码与论文结论对不上；选型判据、超参、口径在代码里和叙述里是两套 |
| 验证堆到结题前 | 把逐问实跑压到最后，长耗时的那一问来不及跑，只能带着未验证状态交稿 |
| 图例遮住数据 | 图例压在数据点上，据被遮区域写出的结论与实际相反 |
| 长表把页尾留白 | 表设 `[H]` 却装不下，整张推到次页，本页尾部空掉近半 |
| 手写文献编号 | 正文上标与文后条目靠人工对齐，增删一条就要全篇改号 |
| 口语化表述 | 「必须强调」「反直觉」「也就是说」「真正的」「好解」「对拍」等进入正文 |
| 残页 | 末页只剩一个孤立字符或一两行，多为截断编辑留下的残迹 |
| 论文里自陈算不出 | 正文写「本题未能求解」「受算力限制未得结果」；这类情况应在对话中告知作者，不进论文 |
| 图内下判词 | 图内文字或图题写「不可行」「显著优于」等结论，而该图并无对应的量可核 |
| 图内标题与图题重复 | 绘图工具的标题与下方「图 N　图题」说同一件事，占版面又啰嗦 |
| 路标词套死 | 四问都用「首先…接着…最后」，读起来像填空模板 |

## 20. 逐问复现门禁（硬要求）

**论文里的每个数字都必须能被附录代码跑出来。** 比任何排版规则都重要，也最容易被跳过。

### 门禁的时点是「每问收尾」，不是「结题前」

**这是本条最要紧的一句。** 实测教训：某次把验证全压到结题前，那时问题二的退火要跑几小时，已经来不及，四问里只有一问真跑过，其余三问带着未验证状态交稿——**不是漏做，是做到那一步时时间已经不够了**。

每问算完当场做三件事，四问分四次做，每次几分钟：

1. **把该问最终脚本跑一遍**，关键输出存档，并记下它对应论文里哪个数；
2. **重跑附录合并脚本**（见 §17），确认合并后的 `qN.py` 仍通过检查。合并脚本要在**第一问做完时就建立**，不是写完论文才拼——这次就是写完才合并，切分点定错，`q1` 一次冒出 11 个未定义名字；
3. **长耗时任务当场后台挂上**。几小时量级的搜索在该问收尾时跑完存档，不留到结题当天。

### 写判断句时当场核对代码

上面三条防的是「没跑」，防不住这一类：代码按「外推平均误差最小」选模型，论文却写「最坏误差最小故选岭回归」。它的产生条件是写代码与写论文是同一个人但在不同时间做的。唯一的防法：

**正文里每写一句「因为 X 所以选 Y」的判断句，当场回到代码里确认该判断就是这么实现的。** 不是写完回头查——回头查时已经不记得代码怎么写，只会凭印象觉得「应该是对的」。选型判据、超参取值、口径定义、阈值来源都属于这一类。

### 数值一致 ≠ 语义一致

实跑复现只能证明**代码与论文报的是同一个数**，证明不了**代码算的是论文描述的那个模型**。
论文里的数本来就是这份代码生成的，两边必然自洽；模型本身错了，数值层一片和谐。

实测教训：正文与调度表都写「07:50 下达准备指令，08:00 可用」，即 10 分钟时滞；而求解器的
准备流水线状态 `(p2, p1, avail)` 的递推使订单在**第三期**才进入可用池，等效时滞是 15 分钟。
所有数值自洽，逐问复现门禁、交叉引用门禁、口语化门禁全部 PASS，无一能发现。更糟的是方向：
更保守的模型判「3 条可行」可以顺推到真实时滞，判「2 条不可行」**不能**顺推——而全篇的
最少性结论恰恰建立在后者上。

以下四条查的是语义，与最终数值无关，应当逐条脚本化。

**S1　时滞、准备期、预热、流水线类参数必须有语义断言。**
不要只核对最终数字，直接断言时序本身：

```python
assert first_available_period(order_at="07:50") == "08:00"
```

任何"下达后 N 期生效""预热 N 步后开始计数""滞后 N 阶"的机制都写一条。这类 off-by-one
在数值层完全隐形，只有语义断言能抓。

**S2　正文写下值函数前，先确认求解器的返回类型。**
正文若写 min–max 值函数 `V_k = min_u max_a {ℓ_k + V_{k+1}}`，代码就必须真的累计 `ℓ_k`、
对控制取最小、对自然取最大，并返回一个数值。若求解器返回的是布尔可行性，正文应写
**安全可行域递推**：

```text
V_k = { s : ∃u, ∀a, F(s,u,a) ∈ V_{k+1} 且本期不越限 }
```

两者的证明强度不同，不能用其中一个的写法去描述另一个的实现。冻结前对照一次
「正文公式的返回类型」与「函数签名的返回类型」。

**S3　表格的每一列都必须指到程序的一个输出字段。**
靠平移、取整、换算从另一列造出来的列不算数据。实测教训：调度表的「指令下达」列由
「实际使用列向前平移两个时段」生成，读者会理解成每期都在重新准备，而真实资源状态是
"已备妥并持续可用"。资源类表格应分列**新增准备 / 准备中 / 已可用 / 实际使用**，且全部来自
策略回放的输出。

**S4　状态压缩键必须与充分统计量论证绑定，并检查论证是否覆盖压缩后的状态。**
memo/哈希键里出现的任何聚合（取整、缩放、求和）都要回答：合并后的两个状态，后续行为是否
一定相同。实测教训：主模型用"剩余队列始终是到达序列的一个**后缀**"论证总剩余工作量是充分
状态量——该论证对精确模式成立；但保守取整的实现是**等比缩放全部批次**，缩放后的队列不再是
任何真实到达序列的后缀，论证失效，而最少性结论正是在取整模式下得到的。
修法是让压缩本身保持充分性：取整只增减**队首批次**的人数（等价于"少服务/多服务一点"，仍是
后缀），而不是等比缩放全部批次。做不到时，把状态签名并入键，或给出正式证明。


**S9　单侧证书必须检查方向，"最少资源"要两侧都有证书。**
用保守近似换状态空间时，近似的方向决定结论能往哪边推：

```text
悲观模型（比真实更严）可行  ->  真实一定可行        悲观不可行  -/->  真实不可行
乐观模型（比真实更松）不可行 ->  真实一定不可行      乐观可行    -/->  真实可行
```

因此"恰好需要 N 个资源"这类结论需要**两张方向相反的证书**：`N-1` 的可靠不可行下界
（乐观模型下仍不可行）与 `N` 的可靠可行上界（悲观模型下已可行）。只拿到一侧时，
写成单侧结论，不要写成最优值。实测教训：一个偏保守 5 分钟的时滞实现使"3 条可行"
仍然成立，却让"2 条不可行"失去依据——顺推方向搞反，整条最少性结论就塌了。

**S10　改了实现，注释与文档字符串必须同步改。**
本轮修好流水线后，函数上方仍留着 `(p2, p1, avail)` 的旧注释；数值层照样自洽，
只有读代码的人会被误导。凡是 S1~S4 涉及的语义（时序、返回类型、状态含义、压缩方式），
改完立刻回头看一遍注释——这本身就是"数值一致 ≠ 语义一致"的一部分。

### 静态检查不等于可复现

实测教训：附录代码通过了语法、未定义名字、逐行等价三项检查，**一跑仍算出与论文不同的结果**——代码的选型判据（平均误差最小）与论文叙述的判据（最坏误差最小）是两套，静态检查查不出来。

**每一问都要真跑**，跑到输出与论文逐位吻合为止。跑不动的（如需要数小时的搜索）至少要跑到能确认它正常进入主循环。

**跑不完、跑不出、对不上的，一律在对话里当面向作者说清是哪几问、卡在哪一步**，由作者决定怎么处理。**绝不写进论文。**

### 四层检查，从便宜到昂贵

1. **语法**：`ast.parse` 或 `py_compile`，秒级。
2. **未定义名字**：`pyflakes`。合并后的文件若用 `from q1 import *`，pyflakes 会放弃分析——**把链上前序文件拼在一起再查**，即可模拟真实命名空间。
3. **逻辑等价**：把源脚本和合并文件都归一化成「去掉注释、空行、import、路径补丁后的代码行序列」逐行比对。这能证明合并没改逻辑，但**证明不了代码本身与论文一致**。
4. **实跑复现**：唯一能发现第 3 层漏掉的那类问题。

### 跑出来对不上时，先分清责任

不要立刻改代码。**先把原始脚本单独跑一遍**：

- 原始脚本也给出同样的"错"值 → 是**代码与论文不一致**，不是合并的锅。此时要判断哪一边是对的：论文若明确写了判据（如"最坏误差最小故选岭回归"），且存档结果与之相符，则**代码是错的，按论文的判据修代码**；
- 原始脚本给出论文的值 → 是**合并引入的问题**，回头查依赖切分与全局变量覆盖。

### 结果目录要隔离

跑验证前先确认脚本的输出路径。若用 `__file__` 相对定位，把代码放在单独目录跑即可自然隔离；否则**先备份 `results/`**。绝不能让一次验证跑覆盖掉论文引用的存档结果。

### 「多跑几次」的含义

一次跑通不等于稳。随机算法要换种子多跑，确认结论不随种子翻转；改过任何判据、超参、口径之后要**重跑并重新核对论文数字**，不能只看"没报错"。

## 21. 改稿操作的安全规则

这几条都是实际造成过损失的。

- **禁止用正则批量删除 Markdown/LaTeX 区块。** `[\s\S]*?` 这类惰性匹配会从第一个起始标记一路吃到目标结束标记，删掉中间大段无关内容。曾因此删掉正文中段十几屏内容。**要删块，先 `Select-String` 定位边界并肉眼确认，再用精确字符串替换。**
- **批量替换必须逐条报告命中数**，并在结束后复查残留。命中数为 0 的条目要当场发现，而不是编译后才知道没改上。
- **`python -c "..."` 在 PowerShell 里会被转义吃掉。** 反斜杠和花括号经过两层解析后面目全非，表现为「替换 0 处」或正则失配。**凡是含正则或 LaTeX 反斜杠的脚本，一律写成 `.py` 文件再执行。**
- **截断编辑后要检查文件尾部。** 删掉一节时容易留下半个代码围栏（如孤立的 ` `` `），它会被渲染成一个孤零零的字符并额外占一页。
- **编号顺延禁止用「插哨兵 + 末尾统一删字符」的写法。** 典型错误：把「表 1~12」整体顺延时
  写成 `for n in 12..1: s = s.replace(f"表 {n}", f"表 {n+1}#")`，最后 `s.replace("#", "")`。
  两处都会出事：其一，`表 1` 是 `表 11#` 的前缀，最后一轮把 `表 10~13` 打成 `表 20~23`；
  其二，`replace("#","")` 连 **Markdown 的 `#` / `##` 标题标记一起删掉**——实测一次删光了
  4 个一级章与 17 个二级标题，编译零警告，图表公式编号检查也全部通过，只有肉眼能发现。
  **正确写法是一次性正则替换**：`re.sub(r"表 (\d+)", lambda m: f"表 {int(m[1])+1}", s)`。
- **改完必须看渲染图，不能只看编译成功。** 编译成功只说明语法对，说明不了版面对。

### 学术语体校订（通读，不是查词）

**这一条的对象是全文语体，不是一张词表。** 一句话可以一个禁用词都不带，读起来仍然像口语：

> 「这样一来求解速度就快多了。」——零个禁用词，仍不是论文的话。
> 改：「该处理使单次求解耗时由 3.2 s 降至 1.9 s。」

**做法：正文冻结前逐段通读一遍，每句问三件事。**

| 判据 | 口语的样子 | 学术的样子 |
|---|---|---|
| 程度有没有落到量 | 快多了 / 差不多 / 比较大 / 明显更好 | 下降 41% / 相差 0.3% 以内 / 高出 2.1 个百分点 |
| 有没有口头语气 | 说白了、其实、当然、可以看出、我们发现 | 删去引导语，直接陈述结论 |
| 动词是否确定 | 应该能 / 基本上可以 / 大概是 | 满足、不满足；已验证、未验证；在本算例下成立 |

含糊的程度副词是最主要来源：**「很、比较、大幅、显著、明显」后面没有数字，就算口语。** 其中「显著」只在给出了假设检验与 p 值时才允许，否则按程度副词处理。

**通读只能由人或模型逐段读，脚本替代不了**——脚本不认识「快多了」这类没有固定写法的表达。

#### 附：高频替换例

下表的词实测反复出现，可以先用脚本扫一遍清掉。**但扫完不等于通读做过了**，它是通读的补充，不是替代。正文出现左列一律替换：

| 口语 | 改为 |
|---|---|
| 对拍 | 交叉校核 / 独立复算 |
| 必须强调（两点） | 需要指出 / 此处有两点需要说明 |
| 反直觉 | 与直觉相悖 |
| 也就是说 | 即 |
| 真正的 | 实质的 / 实际的 |
| 好解 | 优良解 |
| 图中可见 | 由图可见 |
| 说白了 / 其实 | 删去或改为「即」 |
| 需要强调 | 需要指出（或直接删去引导语） |
| 逐位吻合 / 逐位相同 | 完全一致 / 在各档上均相同 |
