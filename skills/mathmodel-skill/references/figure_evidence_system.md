# 数学建模论文图表证据体系

当用户提出“图太少”“图不够优秀”“参考优秀论文改图”“先把图片做出来”
或篇幅审计发现代码结果未进入正文时，读取本文件。目标不是增加装饰图，而是把
模型、数据和验证组织成可检查的视觉证据链。

## 1. 核心原则

1. **图是证据单元，不是排版装饰。** 每张图必须回答一个明确问题，并能对应正文
   中的一项判断、公式、模型选择或可靠性结论。
2. **先做图，再改论文。** 若用户要求先看图片，必须在独立预览目录生成候选图和
   联系表；未经确认不得覆盖正式图或修改论文引用。
3. **参考叙事，不复制表达。** 优秀论文只用于学习“原理—数据—求解—验证”的
   展开次序、图表密度和解释深度，不复制其图形构图、数据、标题或结论。
4. **一图一主任务。** 不把原始数据、FFT、拟合、残差、敏感性和结论塞进同一张
   超载复合图。允许 2×2 或 2×3 子图，但所有子图必须共同回答同一问题。
5. **保留负面结果。** 模型无改进、检验不显著、残差不白、参数强相关等结果同样
   是证据，不得只展示有利图形。
6. **篇幅由证据自然形成。** 增页只能来自必要推导、图表、实验和解释，不能通过
   放大图片、空白浮动、代码截图或重复结论凑页数。

## 2. 图表证据链

根据题型裁剪，而不是机械凑齐。复杂逆问题或物理测量题通常依次需要：

| 层级 | 要回答的问题 | 推荐图形 |
|---|---|---|
| 物理机制 | 信号或决策量怎样产生 | 原创机理图、光路图、变量关系图 |
| 数据审计 | 数据是否完整、异常在哪里 | 原始数据总览、异常点、缺失和量纲 |
| 预处理 | 清洗是否破坏有效信息 | 处理前后、基线、滤除分量 |
| 参数/波段选择 | 为什么使用这些数据 | 滑窗诊断、质量指标、候选区间 |
| 初值与基线 | 求解从哪里开始 | FFT/峰谷/简单模型及粗初值 |
| 主模型拟合 | 模型是否复现实测结构 | 实测—拟合，并把残差单独展示 |
| 模型判别 | 复杂模型是否值得使用 | 公平消融、RMSE/BIC/目标函数对比 |
| 诊断 | 模型还遗漏了什么 | 残差分布、Q--Q、ACF、失败案例 |
| 不确定性 | 结果波动多大 | Bootstrap、置信/分位区间、情景分布 |
| 稳健性 | 结论是否依赖人为选择 | 子频段、参数扰动、边界条件 |
| 可辨识性 | 参数是否可区分 | 相关矩阵、目标剖面、后验分布 |

优化题可把“波段选择/拟合”替换为约束可行域、Pareto 前沿、收敛过程、方案消融
和情景稳健性；预测题可替换为特征审计、滚动预测、误差分布和漂移诊断。

## 3. 实施流程

### 3.1 盘点

1. 列出论文当前所有图片、标签、引用位置和代码来源。
2. 列出代码已经产生但论文未展示的中间结果、诊断、消融和负面结果。
3. 对照每个小问的
   `问题 → 推导 → 求解 → 结果 → 验证 → 解释`
   标记缺失的视觉证据。
4. 区分“应该新增一张图”和“原复合图应拆成多张图”。

### 3.2 预览优先

1. 新图先写入 `figures_v2_preview/` 或等价目录，不覆盖正式图。
2. 生成联系表，统一检查字体、颜色、图例、单位、留白和证据顺序。
3. 先展示联系表及 3–5 张关键图，让用户确认风格和密度。
4. 记录预览使用的参数和结果快照；预览图也必须来自真实运行。

### 3.2.1 增量预览与计算预算

预览、正式重跑和全流水线是三个不同阶段，不得无差别重复执行：

1. **静态审计。** 先扫描统一样式、显式 `fontsize`、inset、重复图例以及
   `suptitle + figure legend + tight_layout` 等高风险组合，不运行模型。
2. **关键图预览。** 首轮只生成受影响的 3--5 张代表图；若问题来自全局样式，再扩展到联系表，
   但仍写入独立目录。
3. **风格锁定。** 关键图通过后一次性生成全部正式图，避免每调整一项颜色或字号就重跑全套模型。
4. **局部编译。** 首次只渲染受影响页面；版式稳定后再执行一次完整论文编译和全页联系表。
5. **最终全流水线。** 只在正式图、论文引用和数值快照均锁定后执行一次完整
   `run_all` 或等价命令。

若单张图生成会重复耗时求解，应优先复用已核验结果快照，或给制图入口增加
`--figures`、`--output`、`--skip-solve` 等选择性参数；不得为了省事把模型重算、正式覆盖和
全 PDF 渲染绑在每次预览中。任何复用都不能绕过最终一次真实全流水线。

### 3.3 正式制图

1. 固定随机种子，原始数据只读。
2. 使用统一配色、字号、线宽和坐标格式；避免仅靠颜色区分，必要时增加线型和标记。
3. 拟合曲线与残差分层展示，避免双纵轴制造视觉误导。
4. 图内标题只陈述对象，结论写入图注和正文；不得在图中声称未经检验的“显著提升”。
5. 示意图必须原创重绘，并与正文符号一致。
6. 输出高分辨率 PNG/PDF/SVG；保证缩放到正文宽度后坐标和图例仍可读。

### 3.3.1 正文缩放后的字号门禁

不得只检查源 PNG 的像素尺寸或 Matplotlib 中填写的字号。必须按论文实际插图宽度估算
缩放后的物理字号：

```text
正文物理字号 ≈ 源图字号 × 论文插图宽度 / 源图物理宽度
```

终稿默认要求：

- 坐标刻度和普通图例缩放后不低于约 7 pt；
- 坐标名称、直接数值标注不低于约 7.5--8 pt；
- 子图标题不低于约 8 pt；
- 流程框或示意图中的关键结论不低于正文小五号字的可辨读水平。

若小插图、局部图例或注释无法满足门禁，不得只提高 DPI。优先依次：

1. 把 inset 改为 nested GridSpec 的独立条带或独立子图；
2. 多子图共用 figure-level legend；
3. 用直接标注替代重复的小图例；
4. 拆图或移入附录；
5. 最后才缩短非关键文字。

### 3.3.2 去默认模板感与“AI 味”视觉审计

“像 AI”不能仅凭浅色或 Python 制图判断；真正需要避免的是默认输出、层级混乱和
结论—证据失配。正式图至少检查：

1. **图内总标题与 LaTeX 图注去重。** 图注已经说明整图任务时，图内不再放同义
   `suptitle`；子图标题只写对象、材料、角度或检验量，不写“显著提升”“验证成功”等结论。
2. **禁止标题—图例碰撞。** 使用独立上边距、共享图例或显式 `subplots_adjust`；
   `tight_layout` 不得与高位 `suptitle`、figure legend 无审计地混用。
3. **不直接交付默认样式。** 固定字体回退、字号层级、线宽、标记、网格、颜色和透明度；
   不依赖 Matplotlib 默认蓝色、默认 12 pt 或未经确认的 SimHei。
4. **浅色只承担区域语义。** 工作带、置信区间和材料层可以使用低透明度浅色；
   主曲线、观测值和模型对照应使用较深、可区分的颜色并辅以线型或标记。
5. **复合图减少重复图例。** 2×2、2×3 图优先共享图例；不得在每个子图塞入
   6--7 pt 的同构图例。
6. **文字不替代证据。** 图内不添加泛化“处理意义”；结论写入图注和正文，并明确
   可见模式、限制和后续影响。

对“频繁分点、公式不规范、章节碎片化”等行文风险应单独审计正文，不能为了降低
所谓“AI 味”机械取消功能性列表、删去公式编号或合并必要章节。

### 3.4 写入论文

每张图附近至少说明：

1. 图中比较了什么；
2. 最重要的可见模式是什么；
3. 它支持或反驳哪项模型判断；
4. 有什么限制或异常；
5. 对后续模型选择、参数设定或决策有什么影响。

禁止只写“结果如图所示”。FFT 粗估、基线结果和最终模型结果必须明确区分，
不能把初始化数值写成正式结论。

### 3.5 复现与一致性

1. 正式图应由独立制图入口生成，如 `code/publication_figures.py`。
2. 保存图表使用的拟合、检验和敏感性数值快照。
3. 建立论文—图文件—结果 JSON 一致性检查，至少核对：
   - 所有 `includegraphics` 文件存在；
   - 正文引用的图均有标签且无重复；
   - 图中厚度、误差、RMSE、BIC、区间和 $p$ 值与结果文件一致；
   - 正式流水线能重新生成图片并编译论文。
4. 对正式图记录文件大小或 SHA-256，可发现旧图未更新和误覆盖。

### 3.6 视觉终审

1. 编译最终 PDF，并逐页渲染为 PNG。
2. 先看联系表查整体密度，再放大检查关键页。
3. 必查：裁切、遮挡、正文缩放后的字号、图例、单位、颜色对比、图题、跨页浮动、
   孤立标题和大片无意义空白。
4. 页面留白若来自章节或附录自然结束可以接受；若来自强制浮动或图片过大，应调整布局。
5. 记录最终页数、文件大小、图数、交叉引用检查和匿名检查结果。

### 3.6.1 长任务进度同步

图表重构可能包含静态审计、预览重跑、正式重跑、编译和逐页检查。每完成一个阶段必须立即
同步计划状态，不能让界面仍显示“检查中”而实际已经进入最终编译。

- 开始耗时命令前说明正在运行的层级：关键图预览、全部正式图或完整流水线；
- 长命令结束后立即报告成功、失败、耗时阶段和下一步，不把多次重跑笼统称为“还在检查”；
- 计划项应按真实完成状态更新；预览通过不等于正式图完成，正式图完成也不等于提交包完成；
- 若发现重复运行会明显增加时间或额度，先检查已有会话、时间戳、哈希和输出，不重复已完成工作；
- 对用户报告“剩余工作”时只列未完成项，并区分 PDF 已完成与 MANIFEST、支撑包尚未同步。

## 4. 优秀论文校准规则

- 先区分参考论文正文、参考文献和代码附录，不能用 PDF 总页数比较。
- 统计参考论文的图表类型和证据顺序，不追求相同图数。
- 优先学习：
  1. 是否先解释机制再给结果；
  2. 是否展示参数选择依据；
  3. 是否拆分拟合与残差；
  4. 是否提供消融、稳健性和失败证据；
  5. 图后是否解释“为什么”。
- 不复制其配色、布局、图注措辞、数据或结论。

### 4.1 跨子问题共用的结构图必须前置

若某张图刻画的对象被两个以上子问题共用（装配树、工艺流程、网络拓扑、状态骨架），它属于
**问题重述或数据预处理**，不属于首次使用它的那一问。

判据：**读者在读到这张图之前，是否已经需要它。** 需要就前置。

2024B 曾把 8 零件–3 半成品–1 成品的装配树埋在问题三（第 12 页），而它是问题二至问题四的
共同基础，读者前 11 页只能靠文字想象结构。前移到数据预处理后，该图落在“依据题面图表推导
出装配树”这句之后，从装饰变成了推导结果的证据。对照的两篇 2024B 优秀论文都把结构图放在
第 3 页。

同理，若正文有一段在说明“各子问题如何承接”，那段话本身通常就是一张图被压成了文字，应
配图放在问题分析末尾。承接图的价值在于标出**什么被下一问继承**，而不是四个方框排一排。

### 4.2 移动浮动体会把问题换个位置

调整浮动体位置后必须重新渲染该页及前后页，不能只看编译无警告。`[H]` 不保证“就在此处”，
只保证不重排到更远处；放不下时会连同后续内容一起推到下一页。

2024B 出现过完整的两步：图插在段落中间会把段落劈成两半；移到节末避开了劈段，却浮到下页
落在**下一节的页眉之下、标题之上**，成为孤儿。最终解是移回段落内并适度收窄图宽。

**排版问题通常不是被消除的，而是被换了位置**，所以每次移动后都要看渲染结果。

## 5. 完成门禁

只有同时满足下列条件，才能声称图表体系完成：

- `reports/figure_audit.csv` 中不存在 `REDESIGN`，所有 `KEEP` 图通过最终插入尺寸可读性、
  灰度和表格重复度审计，所有 `DELETE` 图已从正文移除并记录理由；

- 每个核心小问至少有一张结果图或结果表；
- 主创新有直接对照或消融图；
- 至少一张图展示不确定性或稳健性；
- 重要负面结果被展示或解释；
- 所有定量证据图由真实数据和代码生成；生成式图片不得承担定量结论；
- 图像等级、输入、脚本、快照、SHA-256 和 AI 使用记录已写入溯源清单；
- 正式流水线重跑成功；
- 图表数值与结果文件一致；
- PDF 逐页视觉检查无裁切、遮挡和不可读标注；
- 计划状态与真实产物同步，预览、正式图、最终 PDF 和提交包的完成状态没有混淆；
- 新增页数来自证据，不来自排版填充。

## 6. 可复用结论

一次光谱逆问题的实践表明：把 5 张超载综合图重构为 13 张单任务图，并补充
光路、数据审计、预处理、滑窗选带、FFT 初值、联合拟合残差、多光束判别、
残差诊断、Bootstrap、可辨识性和敏感性后，论文可从 16 页自然扩展到 24 页。
有效改进来自证据链完整性，而不是图片数量本身。此数字只作案例，不构成其他
题目的页数或图数目标。

## 7. 图像来源与证据等级

先判断图像承担什么作用，再选择生成方式：

| 等级 | 图像类型 | 默认生成方式 | 能否作为定量证据 |
|---|---|---|---|
| A | 数据曲线、拟合、残差、分布、热图、敏感性、消融 | Python/R/Matlab 等真实代码读取结果文件生成 | 可以 |
| B | 流程图、模型结构、光路、变量关系、算法框架 | TikZ、SVG、Mermaid、Matplotlib 或其他确定性矢量工具 | 只支撑结构与机制 |
| C | 概念插图、封面式场景、非定量说明图 | 生成式图像工具，可选 | 不可以 |

论文中的定量证据图必须使用 A 级方式，禁止用生成式图片伪造数据点、拟合曲线、残差、
置信区间、热图、参数矩阵、实验截图或表格。复杂示意图优先使用 B 级确定性重绘，以确保
符号、箭头和几何关系可编辑、可核验。

C 级生成式图片只能作为非定量说明，必须：

- 不包含看似真实的实验数值；
- 不承担模型优劣、精度或可靠性结论；
- 对符号、文字、箭头方向和物理关系进行人工复核；
- 必要时在图注中写“示意图”；
- 记录生成工具、用途和人工修改，并进入 AI 使用披露。

## 8. 参考图与满意样式作为风格种子

用户上传喜欢的图、截图或优秀论文图时，不直接复制。先生成
`reports/figure_style_calibration.md`，拆解：

- 字体与中英文字号层级；
- 主色、辅助色、灰度和色盲可读性；
- 线宽、标记、网格和坐标轴风格；
- 子图排列、留白和信息密度；
- 图例位置、单位格式和图注习惯；
- 哪些元素值得采用，哪些因证据或版权风险拒绝。

将确认后的通用样式固化为 `config/figure_style.json`、Matplotlib style 文件或统一绘图
模块。参考图只提供风格方向；数据、构图逻辑、标题、标签和结论必须由当前题目重新设计。

若用户已经明确满意某一批正式图，后续默认继承该样式，不因新建议随意更换配色、字体或
信息密度。只有可读性、合规或证据表达存在明确缺陷时才解冻风格。

## 9. 求解阶段主动建立候选图

不等到 Stage 8 才补图。每个 Qi 完成真实求解后，更新
`reports/figure_evidence_map.md`：

```text
figure_id
对应小问
要回答的证据问题
支持或反驳的主张
图像等级 A/B/C
输入数据或结果文件
生成脚本
候选版式
计划放正文/附录/不采用
当前状态 planned | preview | approved | rejected | formal
```

只为命名主张生成候选图，不因为“每问必须有若干张图”而制造装饰性曲线。代码已产生但
论文尚未展示的基线、消融、诊断、稳健性和负面结果应主动进入候选池。

## 10. 预览、联系表与风格锁定

1. 关键候选图先进入独立预览目录；
2. 生成全体联系表以及 3--5 张原尺寸关键图；
3. 向用户说明每张图为什么需要、来自什么数据、准备证明什么；
4. 用户确认风格后锁定统一绘图样式；
5. 正式图从真实流水线重新生成，不直接把预览文件复制进论文；
6. 不满意的候选保留拒绝原因，避免后续重复生成。

用户没有要求逐图确认时，agent可以按已锁定风格批量完成，但仍须交付联系表和逐图来源
清单。用户明确要求“先看图”时，确认前不得修改论文引用。

## 11. 正式图溯源清单

生成 `results/figure_provenance.json`，每张正式图至少记录：

```text
figure_id
file_path
evidence_question
source_type = data_plot | deterministic_schematic | generative_illustration
input_data_paths
result_snapshot_path
generation_script
generation_command
random_seed
style_config
sha256
paper_section
caption_claim
ai_generated
status
```

每轮正式制图完成后主动向用户报告：

- 新增、重画、拆分或拒绝了哪些图；
- 每张图对应哪个小问和证据问题；
- 数据/结果来源；
- 生成脚本和文件地址；
- 计划放正文还是附录；
- 是否使用生成式工具；
- 一致性与视觉检查结果。

不得只报告“已生成若干张图”而不说明每张图的证据用途和来源。
