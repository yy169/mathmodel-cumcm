# 终稿缺陷校准、评分与停止门禁

用于 Stage 9 已通过基本技术、结构和合规审查后，回答以下问题：

- “最终稿还有什么缺点？”
- “为什么不能满分？”
- “缺少外部真值是否说明没有真实数据？”
- “参数相关是否意味着目标结果不可靠？”
- “求解降维是否需要继续补实验？”
- “与优秀论文相比能打多少分？”
- “还要不要继续改？”

本门禁的目标是区分真正需要修复的问题与题目条件造成的证据上限，避免成熟稿因追求理论满分而反复重构。

## 1. 先分类，再决定是否修改

| 类型 | 判断标准 | 默认动作 |
|---|---|---|
| 事实或合规缺陷 | 数字、公式、引用、匿名、规则或文件不一致 | 立即修复；按影响范围重跑 |
| 核心证据缺口 | 关键结论没有基线、消融、验证或可追溯结果 | 补最小必要证据；无法补时降低结论强度 |
| 主张—证据失配 | 文字声称速度、稳定性、全局唯一性或创新，但现有实验只证明较弱事实 | 收紧措辞，不机械补实验 |
| 表达歧义 | 技术事实正确，但扫读可能得到相反印象 | 做单点澄清性微调 |
| 题目数据上限 | 题面未提供外部真值、额外变量、测量条件或独立验证数据 | 说明边界；不得虚构，也不作为可写作修复的相对缺陷 |
| 理想科研上限 | 需要新仪器、长期实验、扩大样本或独立实验室验证 | 仅作研究展望，不阻塞竞赛提交 |

每项问题必须标记为：

`resolved | mitigated | unchanged_not_a_defect | open`

不得把所有“离理论满分仍有距离”的因素都改写成当前论文缺陷。

## 2. 数据真实性、外部真值与可辨识性

详细判断读取 `judge_view_restructuring.md` 第 16 节。终稿报告时至少区分：

1. 题目附件是否为真实观测；
2. 是否另有独立仪器或标称值提供目标真值；
3. 现有观测能否区分目标参数和伴随参数。

题目提供真实测量数据但未提供独立目标真值时，准确结论是：

> 论文具有真实观测支撑，但外部绝对验证受题目数据条件限制。

不得简化成“没有真实数据支撑”。若同类参考论文也使用同一题内数据，不得只对当前稿追加相对扣分。

## 3. 目标参数与伴随参数分别评价

参数相关不自动等于目标参数不可用。分别检查：

- 目标参数在条件目标函数或剖面中是否有局部单一极小值；
- 初值、子区间、观测条件或基线变化下是否稳定；
- 伴随参数是否存在补偿关系；
- 当前证据是条件局部可辨识，还是联合空间的全局可辨识。

推荐表述：

> 目标参数在多种题内检验下保持稳定；在明确条件下的局部剖面中，目标函数在最终解附近呈单一极小值。但目标参数与伴随参数仍存在相关性，因此伴随参数只作依赖当前模型的等效参数解释。

禁止在只有条件剖面时写“已证明联合空间全局唯一”，也不要只写“参数高度相关”而让评委误读为目标结论整体失效。

## 4. 求解设计的证据等级

| 等级 | 已有证据 | 可以使用的称谓 |
|---|---|---|
| A 数学结构 | 闭式解、条件最优、变量可消元 | 闭式内环、变量消元 |
| B 实现结构 | 外层搜索维数实际降低，代码与公式一致 | 降维求解设计、实现亮点 |
| C 经验性能 | 同条件时间、收敛率、多初值成功率或精度对照 | 提高效率/稳定性，并报告指标 |
| D 独立算法创新 | 文献差异、理论或系统基准均有直接证据 | 算法创新 |

缺少 C 级对照不影响 A/B 级设计的正确性。只有论文要声称“更快、更稳定”或“独立算法创新”时，才需要补性能实验。成熟终稿若已使用 A/B 级克制表述，不应为了满分感继续扩正文。

## 5. 终稿评分校准

用户要求百分制或与优秀论文比较时：

1. 明确评分是内部启发式，不对应、也不预测奖项；
2. 给出点估计和合理波动范围，默认说明主观误差约为 `±2`；
3. 比较对象必须口径一致：正文与代码附录分开，公开优秀论文的历史结果与内部稿的启发式评分分开；
4. 题面共同缺失的外部真值不得成为只针对当前稿的相对扣分项；
5. 纯措辞修改只能提高阅读、语言或误读风险维度，不能伪装成模型严谨性或实验分数上升；
6. 总分变化小不代表修改无价值。终稿微调的主要收益常是降低低概率高代价的误判；
7. 评分结论同时报告最强项、仍受数据限制的边界和停止理由。

推荐输出结构：

```text
总分与区间
已解决
已缓解
未改变但不构成缺陷
仍开放且需要新证据
是否继续修改
```

满分只表示理想化的证据、表达、合规和外部验证全部具备，不是竞赛稿必须达到的现实阈值。

## 6. 澄清性微调协议

技术和结构已经冻结后，只允许针对明确误读风险做单点修改：

1. 写明误读风险和现有证据边界；
2. 锁定模型、数值、图表、结论和证据位置；
3. 一项风险对应一个最小文字补丁；
4. 不顺手改写相邻稳定段落；
5. 精确匹配旧文本并保留修改前备份；
6. 重新编译，检查日志和受影响页面；
7. 同步源码、权威 PDF、AI 日期、状态、报告、MANIFEST 和支撑包；
8. 记录旧权威文件与新权威文件，防止提交错版。

若写入命令在解析阶段失败，先确认文件未变化，再改用精确匹配脚本；若流程在中途失败，后续脚本必须可幂等重试，不能假定所有步骤均未执行。

## 7. 停止规则

满足以下条件后冻结正文：

- 所有事实、数值、引用和合规门禁通过；
- 核心结论有题内证据闭环；
- 创新强度与直接证据匹配；
- 局限没有被掩盖，也没有被写成核心结果失效；
- 剩余不足只能通过新数据、新仪器或独立性能实验解决；
- 权威 PDF 与支撑包已同步并核验。

此后除发现明确错误、规则变化或新增真实证据外，不再因为“还能更好”而继续修改。
