# 评委视角结构重构与多轮改稿门禁

当技术计算已经稳定，而用户要求“按评委视角重构”“参考优秀论文逐节精修”
“结论前移”“把完整诊断放附录”“已经改了多轮，先判断为什么改”时读取本文件。

本流程解决的不是模型选型，而是技术底座稳定后的信息架构、证据分级、多轮修改
一致性和提交包同步。与 `paper_depth_audit.md`、`figure_evidence_system.md`
配合使用，不替代真实计算、语言终审或 LaTeX 预检。

## 1. 总原则

1. **先锁定技术底座，再改阅读顺序。** 模型、公式、结果 JSON、正式图表和关键
   数值未锁定时，不进入结构重构。
2. **结论前移不等于证据删除。** 先给评委结论和核心表图，再保留必要证明；
   完整诊断转入附录时，正文必须保留结论、关键数字和附录引用。
3. **不按固定比例删减。** 不执行“必须删除 15%–20%”之类机械目标。按内容作用
   决定“保留、前移、压缩、下沉或删除重复”。
4. **优秀论文只校准阅读体验。** 学习其证据顺序、段落层级和结果呈现，不复制
   文字、图形、数据、配色或结论，也不把参考论文页数当获奖阈值。
5. **每轮修改都要能回答为什么。** 没有明确问题、证据和验证方案的修改不执行。

## 2. 接续旧任务时先恢复现场

除当前文件状态外，还要检查上一任务的完整对话或修改日志。不得只阅读最终答复或
最近几轮。若存在多阶段结果更新、摘要回退、图表预览或“已完成”结论被后来推翻，
读取 `references/revision_case_history.md`，重建“修改—原因—结果—是否保留”的时间线。
对话结论必须与当前文件和真实运行交叉核验。

开始编辑前：

1. 定位实际项目目录；不要把新任务默认工作区误当成论文目录。
2. 读取 `state/decision_log.json`、最新报告、主源文件、结果文件和编译产物。
3. 检查 Git 状态；若项目不是 Git 仓库，明确说明并使用最近备份执行
   `git diff --no-index` 或等价文本比较。
4. 按修改时间列出主论文、制图脚本、一致性脚本、结果快照、PDF 和报告。
5. 先汇报“已完成、未完成、风险、接续计划”，再继续编辑；不得从头重做稳定工作。

不得用无关目录的 Git 状态代表论文状态，也不得因为没有 Git 就声称没有修改。

## 3. 建立不可变技术基线

在结构重构前记录：

- 最终模型及弃用模型；
- 每问的 headline result、单位和有效数字；
- 基线、消融、区间、敏感性、负面结果；
- 正式结果 JSON、图表数值快照和随机种子；
- 当前图数、表数、页数、引用数和 PDF 哈希；
- AI 使用日期、工具和披露文件。

结构改稿期间默认这些内容不可改变。若文字调整暴露技术冲突，停止写作并触发
定向 L2 回检；不要在 LaTeX 中手改数字掩盖冲突。

## 4. 修改前先分类，不直接动稿

对每条外部意见独立判断：

| 类型 | 处理 |
|---|---|
| 结论埋得太深 | 前移到小节开头、流程图或核心结果表 |
| 关键证据缺失 | 从真实结果补入正文 |
| 完整诊断抢主线 | 正文保留结论与关键数字，完整图表下沉附录 |
| 重复解释 | 合并或删除重复段落 |
| 通用算法教材化 | 压缩为本题作用、参数和选择理由 |
| 有价值负面结果 | 保留，不为“结果漂亮”而删除 |
| 缺少直接验证的创新话术 | 降级为求解设计、实现亮点或候选改进 |
| 仅为凑页数或模仿参考论文 | 拒绝 |
| 会改变模型、数据或结论 | 回到 Stage 3–7，不作为文字微调处理 |

把意见分为“立即采纳、条件采纳、暂不采纳”，不要因意见来自优秀论文或评审者
就自动执行。

## 5. 评委阅读主线

技术型三问论文优先形成：

`摘要结果地图 → 三类难点/对应策略 → 总流程图 → 每问结论 → 核心模型与结果
→ 核心结果总表 → 关键验证 → 贡献与边界 → 附录完整诊断`

总流程图必须连接：

`难点 → 策略 → 数据/算法 → 最终模型或方案 → 可靠性`

避免只画“数据 → 建模 → 求解 → 结论”的通用流水账。图内标题若与 LaTeX 图题
重复，应删除图内大标题，把空间留给证据内容。

## 6. 正文与附录的证据等级

正文至少保留：

1. 一个独立、可解释基线；
2. 一个主创新的直接对照或公平消融；
3. 一项不确定性或稳健区间；
4. 一项对人为选择或工程参数的敏感性；
5. 一个负面结果、失效条件或模型形式不确定性；
6. 对最终结论的物理/业务解释。

适合下沉附录的完整证据：

- 预处理全链和被滤除分量；
- FFT 完整频谱与粗初值；
- 置换、循环移位或 Bootstrap 的完整分布；
- Q--Q 图、ACF 和多组残差诊断；
- 参数相关矩阵、局部目标剖面和次要敏感性面板。

“下沉”不等于“消失”。正文必须说明图证明了什么、保留关键数字并引用附录标签。

## 7. 问题三和复杂模型判别

当题目要求判断复杂模型是否必要时，优先顺序为：

`必要条件 → 复杂模型公式 → 同条件公平消融 → 独立统计旁证`

公平消融至少保持数据范围、材料先验、标定规则、优化器和评价指标一致。统计检验
只作旁证时，应明确降级，不让长统计推导先于物理模型比较。复杂模型无实质收益的
负面结果必须保留，它能证明模型复杂度由证据控制。

## 8. 创新点与求解亮点

最终正文通常只保留：

- 1–2 个有直接证据的核心创新；
- 最多 1 个本题特化的求解设计亮点。

若只证明了闭式消元、变量降维或条件最优，不得自动写成独立创新算法。缺少运行时间、
收敛率、多初值成功率或消融对照时，应称“降维求解设计”或“实现亮点”。

不要在论文中写“本文不夸大”“不是为了包装创新”等审稿式元话语。直接陈述可验证
事实，例如“保持条件最优标定，并将外层搜索由 7 维降至 3 维”。

## 9. 摘要与关键词最后定稿

正文稳定后再做摘要最后一轮：

1. 第一段先写核心矛盾和统一框架，不堆 Lorentz、FFT、AsLS 等工具清单。
2. 后续按子问题写“模型/方法 → 关键结果 → 验证或边界”。
3. 只保留能帮助判断的 headline values，不把摘要变成结果表。
4. 每个数字必须回指正文和结果文件。

关键词同时满足“可识别”和“建模术语”：

- 不要全部使用“参数估计、模型拟合、分析”等过泛词；
- 不要全部使用题目对象或行业背景词；
- 采用“对象/任务 + 模型/算法/检验”的组合；
- 运行竞赛 LaTeX Skill 的关键词检查；必要时把对象词与“参数估计、最小二乘、
  优化、统计检验、敏感性分析”等方法词组合。

## 10. 稳健性和模型评价的取舍

稳健性章节证据丰富不等于必须删除。只有在阅读节奏或页数确有压力时才下沉次要检验。
工程意义更强的参数优先留正文；纯预处理参数敏感性可先考虑附录。

模型评价建议：

- 优点压缩为约 3 条，每条必须有结果或结构证据；
- 局限保留具体触发条件、受影响结论和改进路径；
- 保留模型形式不确定性、参数相关性和有效数字边界；
- 不把负面信息润色成“精度高、稳定性好、适用性强”的套话。

## 11. 多轮改稿日志

每一轮维护结构化记录：

```json
{
  "date": "YYYY-MM-DD",
  "trigger": "用户/评审意见或检查发现",
  "problem": "为什么需要改",
  "decision": "keep | move_forward | compress | move_to_appendix | rewrite | reject",
  "reason": "证据与风险权衡",
  "invariants": ["不得改变的模型、数字、图表"],
  "files_changed": [],
  "validation": [],
  "outcome": "pass | revert | pending"
}
```

建议写入 `decision_log.stages.9.redo_log` 或独立的
`reports/structure_revision_log.md`。每轮结束同时记录“为什么不改某些内容”，防止下一轮
重复推翻已稳定决策。

## 12. 按修改类型选择验证强度

| 修改 | 最低验证 |
|---|---|
| 纯措辞、关键词 | 术语/数字检查 + LaTeX 编译 + 受影响页面渲染 |
| 章节移动、附录下沉 | 全部交叉引用 + 页数分界 + 全 PDF 联系表 |
| 表格或流程图 | 编译日志溢出检查 + 原尺寸页面检查 |
| 图形脚本或图中数值 | 真实重跑 + 数值快照 + SHA-256 + 全文一致性 |
| 模型、工作带、参数或结果 | 回到 Stage 3–7，重新执行基线、消融和稳健性 |
| AI 日期、图数或用途变化 | 同步论文、披露 PDF、decision log、README 和提交包 |

文本微调不必无意义地重跑全部优化，但必须重新编译并核对数字；涉及图表或结果时必须
完整重跑。

## 13. 排版中容易忽略的细节

- 中文 `tabularx` 的 `X` 列可能产生夸张字间距；对结论列使用
  `>{\raggedright\arraybackslash}X`，对固定列使用明确的 `p{}` 宽度。
- 编译成功不代表排版通过；检查 Overfull、Underfull、跨页浮动、孤立标题和附录分页。
- 宽表、流程图、摘要页、创新段、参考文献和最后一页必须原尺寸检查。
- PDF 被预览程序占用时，不要声称已覆盖；保存新的权威文件名并写入状态和交付说明。
- 页数从 24 变为 23 可能只是去掉重复标题或修复表格，不应被解释为技术删减。

## 14. 提交包同步门禁

多轮修改最容易遗漏“正文已更新、提交包仍是旧版”。每次最终微调后同步：

- `paper/main.tex` 与最终 PDF；
- 正式图、结果快照和一致性报告；
- `decision_log.json` 的页数、图数、AI 日期和 authoritative PDF 路径；
- README 的页数、图数、依赖安装和运行命令；
- AI 工具使用详情；
- 支撑材料 MANIFEST、ZIP 哈希和文件大小。

支撑包排除虚拟环境、缓存、备份、优秀论文、渲染中间目录和本机绝对路径脚本。必须在
无预设环境变量的状态下测试一键入口，或明确给出 `pip install -r requirements.txt`。

## 15. 冻结与停止条件

当一节已完成“技术一致、评委可读、证据充分、排版通过”后将其冻结。后续意见只在出现
新证据、规则变化或明确缺陷时解冻，不反复润色已稳定段落。

满足以下条件即停止全局修改：

- 无高严重度技术或合规问题；
- 评委主线能在摘要、流程图、每问结论和核心结果表中快速恢复；
- 正文保留最低核心证据，附录保留完整诊断；
- 创新强度与直接证据一致；
- 全流水线、引用、匿名、AI 披露、逐页视觉和提交包检查通过。

停止后只允许低风险微调，并按第 12 节执行相应验证。

## 16. 区分数据真实性、外部真值与参数可辨识性

终审评分或模型局限分析不得把以下三件事混为一谈：

1. **真实观测数据**：题目附件来自实际测量时，论文已经具有真实数据支撑；
2. **外部目标真值**：独立仪器、标称值或破坏性测量给出的目标参数真值，用于外部验证；
3. **参数可辨识性**：现有观测能否区分目标参数与伴随参数的不同组合。

若题目未提供外部真值，且同类优秀论文也只能使用题内数据，不得把“缺少外部真值”列为当前论文可通过写作修复的相对缺陷，更不得虚构标称值。它只能作为理想科研条件下的证据上限。此时应使用题内证据闭环：独立基线、不同观测条件共享参数、同条件模型消融、重采样区间、子区间稳定性、目标函数剖面和模型形式敏感性。

参数相关不等于目标参数不可用。应分别说明：

- 目标参数是否在局部目标函数中具有唯一且尖锐的极小值；
- 目标参数是否在子区间、初值和观测条件变化下稳定；
- 伴随参数是否仅具有依赖模型的条件可辨识性。

局限段避免只写“目标参数与其他参数高度相关”而让评委误解为最终结论失效。优先写成“目标参数经剖面和稳定性检验仍具有局部唯一性，但伴随参数存在补偿关系，因此伴随参数只作等效参数解释”。

闭式消元、变量投影或内外环降维在没有效率对照时仍可作为正确的求解设计。只有要把它提升为独立算法创新，才需要增加同条件的运行时间、收敛率、多初值成功率或维数消融对照。不得把缺少这类对照误写成模型正确性不足。
