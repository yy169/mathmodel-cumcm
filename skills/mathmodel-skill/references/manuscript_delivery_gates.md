# 正文与交付门禁

在 Stage 8 初稿形成后、Stage 9 定稿前读取。目标是同时阻止“题目漏答”和“写得像完成”。

## 1. 正文六层矩阵

为每个核心小问建立 `reports/manuscript_evidence_matrix.csv`，分别登记：

1. `problem_analysis`：真正难点、易错机制和路线理由；
2. `model_formulation`：变量、公式、约束和现实语义；
3. `solver`：算法步骤、终止/可行条件与计算实现；
4. `result`：真实运行、理论命题或可核验方案；
5. `validation`：对拍、消融、敏感性、稳健性或证明；
6. `interpretation`：结果机制、决策含义和适用边界。

各层只允许 `PASS/PARTIAL/FAIL/BLOCKED/NA`。纯理论题可将不适用层标为 `NA`，但必须
说明理由；不能用固定字数、页数或图数替代证据审计。

## 2. Claim证据等级

在 `reports/claim_registry.csv` 增加 `evidence_level`：

- `structural_proof` / `formal_derivation`：结构性命题或形式推导；
- `exact_enumeration`：完整有限空间的确定性评价；
- `numerical_validation`：有误差控制的数值验证；
- `empirical_crosscheck`：经验旁证，不承担证明；
- `sensitivity_only`：只支持局部稳健性；
- `source_supported` / `direct_result`：文献或权威结果直接支持。

“证明、不可能、唯一全局最优”等强措辞必须匹配结构证明、形式推导或精确枚举。有限轮
仿真、数量巧合和敏感性结果只能写成相应等级的旁证。

强措辞清单不止这三个词，**下列词同样要按 Claim 等级审**，实测中它们最容易漏网：

| 词 | 要求 |
|---|---|
| 最不利 / 最坏 / 最优组合 | 必须先给出判据（按什么指标最不利），否则改写为"代表性高压情景" |
| 唯一 / 唯一化 | 单调性只能保证"最坏值**可在**上角点取得"，不足以支持"最不利点**唯一**" |
| 下界 / 上界 / 证书 | 要写明是哪种松弛下的界；上下界不相合时给区间，不要只报其中一端 |
| 最少 / 恰好需要 N | 需要"N 不可行 + N+1 可行"两侧证据；只有一侧就写成单侧结论 |

## 3. 编码与动作可复核性

论文出现策略编号、位串、染色体或状态索引时，建立 `reports/encoding_registry.csv`，记录
编码公式、展示顺序、动作解码表、至少一次程序往返测试及证据路径。不得默认编号就是常规
高位优先二进制。

## 4. 语义和受控情景

- 会改变目标函数、状态空间、成本或策略集的语义，必须记录工序解释、是否题面唯一、备用
  分支和敏感性结果；无法唯一推出时分支建模或请求确认。
- 题面没有真实观测时，参数化的 `(n,k)`、合成样本或中心情景必须在正文、表格和摘要统一
  标为“受控情景/参数化结果”，禁止写成实际企业观测。
- 出现信度、显著性、两类错误、功效、OC、后验区间或预测区间时，读取
  `statistical_semantics_gate.md`；原题措辞、数学约束和正文结论未一一对应前不得冻结。

## 5. 逐节冻结

章节状态固定为 `draft → reconstructed → validated → frozen`。冻结后只有新证据、数字冲突、
规则变化或明确排版缺陷才能解冻；删去重复图、调整图注或排版不得触发模型重跑。

## 6. 派生式门禁

运行：

```bash
python <skill>/scripts/run_readiness_audit.py --project <cwd> --output-dir <cwd>/reports/readiness
```

`manuscript_ready` 必须由 Requirement、Claim、六层正文、图表、编码和跨文件检查派生，禁止
手写布尔值。核心项存在 FAIL 时只能形成诚实降级的应急稿，不能称为高质量 final。

## 7. 冻结前的机械检查

以下三项不需要判断力，全部可脚本化。规则写进文档会被忘记，写进门禁不会。

### 7.1 浮动体必须被正文引用（反向检查）

`figure_evidence_system.md` §3.5 已要求“正文引用的图均有标签”，那是 `\ref → \label`
方向。**还必须做反向检查**：每个 `\label` 都要至少被一次 `\ref` 命中。

```text
unused = {所有 \label} - {所有 \ref}      # 符号说明表按惯例可白名单排除
```

2024B 终稿曾有 16 个浮动体中的 5 个从未在正文出现引用，编译无任何警告，只有全文通读
才发现。评委看到无人提及的图会问“这张放在这里做什么”。

补引用时不要写“如图 N 所示”了事，应带入该图独有的信息，否则等于承认这张图可删。

### 7.1b 不用 `\ref` 时，改在编译后的 PDF 上做等效检查

上一条的前提是正文用 `\ref{}` 交叉引用。实践中由 Markdown 经 pandoc 生成的稿子往往
**一个 `\ref` 都没有**——「图 3」「表 11」「式 (7-4)」全是手写汉字。实测一份终稿：
36 个 `\label`、**0 个 `\ref`**。这种稿子改任何一个编号，LaTeX 不会给任何警告。

改写成 `\ref` 风险大且不改变外观，更划算的做法是在编译后的 PDF 上做等效检查：

1. **编号连续**：图题、表题从 1 起连续无缺号无重号；
2. **引用存在**：正文引用的每个「图 N / 表 N / 式 (x-y)」都真有对应对象；
3. **反向覆盖**：每个图表至少被正文引用一次（符号说明表按惯例白名单排除）；
4. **页距合理**：引用与被引对象相隔超过两页的，逐条确认是有意的跨章回指；
5. **章节结构**：一级章号连续、章标题与规范章序一致；每章的二级标题编号连续。

第 5 条不是凑数。实测：一次批量替换误删了 Markdown 的 `#` 标题标记，4 个一级章与
17 个二级标题整体退化为正文段落，**编译零警告，第 1~4 条也全部通过**，只有肉眼能发现。

**二级标题不能用正文文本正则识别**：表体里的「17.7329」「8.9」与「章.节」长得一样。
按字形判定才可靠——导言区把 subsection 编号设为 `\heiti\bfseries`，落到 PDF 里是
`*-Bold` 12pt，而正文数字是 `*-Regular` 11.96pt，用 `page.get_text("dict")` 的
span 字体名与字号可严格区分。

### 7.2 删除计算产物前先搜正文

删除或重命名 `code/`、`results/` 下任何文件前，先用其产生的数值在 `paper/*.tex` 中检索；
命中则拒绝删除，或要求同步修改正文。

2024B 曾把一个参数扫描脚本连同其 CSV 一并删除（判定为“未采纳的探索，不留垃圾”），但
正文已经引用了该扫描得出的切换增量。结果是论文里留下一个仓库中无法复现的数字——这违反
本技能最基本的一条纪律，而删除动作在当时看完全合理。

**探索性计算被否决时，被否决的是它的结论，不是它已经进入正文的中间结果。**

### 7.3 交付包与状态日志的自引用顺序

支撑材料包通常内含 `state/decision_log.json`，而该日志又记录支撑包的 sha256。二者无法
同时自洽，顺序必须固定：

```text
1. 重新编译 → 2. PDF 哈希写入日志 → 3. 打包（包内日志已含正确 PDF 哈希）
                                   → 4. 最后把包哈希写回日志
```

包自身的指纹必然滞后一步，这是自引用结构的固有性质，应写明而不是反复重打包试图消除。
先打包后更新日志会让包内日志记着上一版的 PDF 哈希，且外部校验不会报错。
