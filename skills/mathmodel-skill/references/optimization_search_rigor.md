# 优化与搜索的严谨度门禁

当某个子问题的交付物是**一个被搜索出来的设计/方案/子集**（而不是一次拟合、一次预测或一次
评价）时读取本文件。典型触发词：设计参数、选址、选型、取舍、排产、布局、分配、组合优化、
"使……最大/最小"。

这类问题的失败模式与拟合类问题**完全不同**：拟合类的风险是"算错"，搜索类的风险是
**"算对了，但算的是错的东西"**——内核自洽、收敛曲线漂亮、断言全过，而结论仍然偏了。
本文件的每一条都对应一种"全部自检都会通过"的失败。

Stage 5 Step C 之后、Stage 6 之前执行。每条给出：**通用规则 → 触发条件 → 检查动作**。
末尾的案例编号指向 §13 的实测证据。

---

## 0. 一句话总纲

> 算法自检（精确性、收敛、不动点、单调性）在**题意读错或代理口径错**时**全都会通过**，
> 因为内核是自洽的，只是自洽在错的问题上。

因此本文件的门禁分两类：**§1–§3（含 §1.5）检查"在解正确的问题吗"**，
**§4–§12 检查"搜索做到位了吗"**。前者优先级高于后者：口径错时，把搜索做得更精细
只会让错误更精确——目标本身选错时尤其如此，因为下游全部验证都会显得自洽。

## 1. 题面符号逐条对账（非算法性检查，最高优先级）

**规则**：最终公式与代码里出现的**每一个符号、常数、口径**，逐个追回题面原文，形成对账表。
这是唯一一道不依赖代码正确性的检查。

**触发**：所有搜索类问题，在锁定交付结果前执行一次。

**检查动作**：建一张表，每行 = 一个符号/常数，列为「代码取值 | 题面原文位置 | 是否一致」。
必须覆盖：

- 起算原点与计数口径（第 0 天是哪天、索引从 0 还是 1、区间开闭）；
- 单位与量纲换算，尤其是题面混用两种单位时；
- 题面**没说**要做的修正，代码是否擅自做了（时制换算、经度修正、归一化、去量纲）；
- 边界值的取等方向（`≥` 还是 `>`，"多 5 m 以上"是 `>` 还是 `≥`）；
- "平均"的口径：等权、加权、按什么加权，题面是否指定；
- 几何/物理量的定义域（哪一段区间、哪个面参与计算）。

**为什么必须单列**：本项目 12 项对账全部对上，但这道检查的价值不在"发现了错"，
而在它是**唯一能发现题意误读的检查**——其余所有检查都建立在"题意读对了"的前提上。（案例 C10）

## 1.5 目标函数台账：重述的是代理目标，不是原目标

**规则**：题面原始目标（通常是**比值**：单位成本产出、性价比、单位资源收益）如果在建模中被
重述为另一个问题（通常是**规模**：最小成本、最小资源、最大规模），必须像消元决策变量一样
登记，不能只写一句"在最优处两者等价"就直接换题。

**触发**：目标函数含分式（`E/A`、单位产出、性价比），且代码/推导中出现了"重述为""等价于"
"因此转化为"这类措辞把分式目标换成了规模目标。

**为什么这条容易被漏**：换题之后的下游全部工作——精确性分档（§3）、暴力穷举对拍、
交换邻域证书（§5）——都会显得无懈可击，因为它们确实**精确解出了代理目标**。
但精确解出代理目标，不等于精确解出原目标。这和 §0 的总纲是同一个道理，
只是这次自洽的对象是整个求解流水线，而不是某一段代码。

**"最优处约束取等"不能替代等价性证明**。反例：方案 A 面积 10、单位产出 0.60、总产出 6.00；
方案 B 面积 9、单位产出 0.56、总产出 5.04；门槛 5.00。`min A` 选 B（9<10），
原目标 `max E/A` 选 A（0.60>0.56）——两者选出不同方案。约束在原目标最优处确实取等
（多留一个低于均值的单元只会拉低比值），但这只保证**原目标的最优解满足约束取等**，
不保证**代理目标（min 规模）的最优解等于原目标的最优解**。两个命题不是一回事。

**检查动作**：

1. 写出题面原始目标的精确数学形式，与代码实际优化的目标**并排**列出；
2. 若两者不是同一个表达式，问：**是否存在严格等价性证明**（不是"直觉上应该一样"）？
   - 有严格证明（如本文件 §3 表中"各单元成本相等"这一档，规模目标与比值目标此时确实
     同解）→ 登记为 `EQUIVALENT_BY_PROOF`，附证明；
   - 没有证明，只是"看起来合理" → 登记为 `PROXY_UNVERIFIED`，进入第 3 步；
3. 对 `PROXY_UNVERIFIED`：在**当前实际候选集**（不是合成数据）上，独立写一版直接优化原目标
   的版本（哪怕是暴力枚举），与代理目标给出的解**对拍**：
   - 若两者选出同一集合 → 在论文里用这个对拍结果**支撑**"代理目标在本实例下与原目标同解"，
     措辞仍然是"数值验证同解"而不是"数学等价"；
   - 若两者选出不同集合 → 代理目标的解不能再叫"精确最优"，必须换成直接优化原目标的版本，
     或者明确将代理解降级为"下界近似"；
4. **暴力穷举对拍的 oracle 本身必须优化原目标**。如果 oracle 也是"暴力穷举 min 规模"，
   那么"与暴力穷举逐位相同"只证明"代理目标求对了"，不能作为原目标正确性的证据——
   这是最容易被忽视的一点：验证代码继承了建模阶段的同一个替换，检验因此在验证错误的东西。

**边界感**：不是所有重述都需要走完整流程。若各单元成本严格相等（§3 表第一档），
最小成本 ⇔ 最小个数 ⇔ 按收益降序取前缀，这本身就是规模目标与比值目标同解的证明，
可以直接登记 `EQUIVALENT_BY_PROOF`。**只有成本不等或收益耦合时，才必须做第 3 步的对拍**。
（案例 C16）

## 2. 决策变量审计：题面给的每个自由度都要有交代

**规则**：把题面**明文列为设计对象**的每一个变量登记入册，每个变量必须落到四类之一，
不允许"没提到"这一状态：

| 状态 | 含义 | 是否需补测 |
|---|---|---|
| `SEARCHED` | 实际做过数值搜索，记录范围与步长 | 否 |
| `FIXED_BY_PROOF` | 由可写出的论证固定，且论证前提在本题成立 | 否，但要复核前提 |
| `FIXED_BY_HEURISTIC` | 由"听起来合理的一句话"固定，未做反方向探针 | **是，全部** |
| `GIVEN` | 题面规定，不是决策变量 | 否 |

**触发**：Stage 5 中任一子问题出现"设计/确定/给出……参数"的措辞。

**检查动作**：

1. 从题面原句里抄出设计对象清单（抄原句，不要转述）；
2. 逐项标注状态；
3. **对每一个 `FIXED_BY_HEURISTIC` 做反方向探针**：朝那句话说"会变差"的方向实测 2–4 个点；
4. 探针用粗档位即可，但每点必须**重新生成候选并重新走完整取舍**，不能只换参数不重算下游；
5. 探针结论写入 `decision_log`，正文局限一节按"**已测过并排除**"与"**未搜索**"分别措辞。

**两条容易漏的**：

- **`FIXED_BY_PROOF` 的前提会失效。** 同一条论证在 Q2 成立、在 Q3 未必——放开某个约束后
  原证明的前提可能刚好被破坏。分问题重新标注，不要跨问题沿用状态。
- **从未取过非默认值的自由度**（相位、取向、初值、排序方向、tie-break 规则）也是自由度。
  哪怕只扫一遍确认默认值最优，也比"从来没想过"强。（案例 C8）

**最重要的一条经验**：**取值对 ≠ 理由对。**
本项目四项探针全部确认原取值最优，但其中两项的**原理由是错的**。错的理由不影响当前数字，
却会在条件变化时把结论带偏——其中一条错误理由正是另一个问题漏掉整个自由度的直接原因。
探针的产出因此不只是"改不改"，还包括"**理由要不要重写**"。（案例 C1）

## 3. "精确最优"的成立条件必须分档，不能笼统宣称

**规则**：任何"按某个指标排序取前缀即最优"的结论，都有**明确且狭窄**的成立条件。
写进论文前先定位自己落在哪一档。

**典型分档**（以"用最少资源凑够指标"类问题为例）：

| 情形 | 严格程度 | 说明 |
|---|---|---|
| 各单元**成本相同** | 0-1 问题的**精确最优** | 最小成本 ⇔ 最小个数，按收益降序取前缀即最优 |
| 成本不等、收益**冻结** | 分组前缀枚举可得**精确最优** | 同成本组内必为收益降序前缀，只需在"各组各取几个"的低维网格上枚举 |
| 收益与选择集合**耦合** | **逐轮精确、自洽稳定**，不宣称全局最优 | 见 §4 |

**触发**：出现"贪心""按密度排序""按性价比取前缀"且论文里想写"最优"。

**检查动作**：

1. 问一句：**各单元的"成本"是否相等？** 不等就不是可分割背包，密度排序对 0-1 问题一般不最优；
2. 若不等但成本只有少数几档 → 按成本分组，组内必为前缀，在"各组取几个"的低维网格上枚举，
   即为冻结收益下的精确解，复杂度仍是 `O(N log N)`；
3. 与**暴力穷举对拍**（小规模随机算例几百组），确认逐位相同；
4. 论文措辞按上表分档写，**不要用一个"精确最优"盖住三种情形**。

**边界感**：分组枚举相对密度贪心的改进往往很小（本项目 0.009%），差距上界约等于"一个单元的成本
占总成本的比例"。**改进小不是不做的理由**——做它的收益是措辞可以从"近似"升级为"该档下精确"，
这是论文可信度而非数值收益。（案例 C2）

## 4. 目标与选择集合耦合时：迭代到不动点，但不动点 ≠ 最优

**规则**：若个体收益 `g_i` **依赖于最终保留了哪些个体**（互相遮挡、互相竞争、共享容量、
排队干扰、网络效应），则单轮取舍必然不自洽——用旧 `g` 选出的集合，其真实 `g` 已经变了。

**触发**：`g_i` 的计算里出现了"其他个体"。这是判据，不需要更多理由。

**识别信号**：**上报值明显高于预测值**。若"按预测应该刚好达标"而实际算出来超出一截，
说明多留了本可剔除的单元，余量就是耦合造成的偏差。

**检查动作**：

1. 用当前集合的**真实** `g_i` 做精确取舍 → 集合收缩 → 重算 `g_i` → 再取舍，直到集合不再变化；
2. 保存迭代轨迹（每轮的目标值、剔除数、保留数），它本身就是论文里的一张表；
3. **不要宣称全局最优**。只删不加的单调收缩保证**终止**，不保证**最优**：
   某个单元可能在早期因被邻居压低 `g` 而被删，而后来压制它的邻居也被删了，
   单调收缩的流程不会回头重新考察它。

**必须补的一步**：既然不动点不是最优，就要给一道**邻域最优性检验**（§5）。

（案例 C3）

## 5. 交换邻域检验：三个几乎必踩的坑

**规则**：不动点解上做"放回一个 + 删除若干"的交换枚举，作为局部最优性证据。
这一步有三个独立的坑，每个都会让检验失效。

### 5.1 整数性改变门槛

放回单元 `j` 要让总成本下降，得删掉一组 `T` 满足 `Σ_{i∈T} a_i > a_j` 且 `Σ_{i∈T} a_i g_i ≤ a_j g_j`。
**删除量是整数。** 若把判据写成 `g_j > min_i g_i`，那是把删除量当连续可分的结果，**门槛系统性偏低**。
等成本时加一个必须删**两个**才省得下成本，真实门槛是 `2·min_i g_i`。

**检查动作**：手推一遍"最少要删几个才能净省"，把那个整数写进判据。（案例 C4）

### 5.2 冻结 `g` 会系统性低估删除的收益

冻结 `g` 的判据漏掉两项二阶效应：放回的单元给邻居**添**干扰、删除的单元**释放**邻居。
删掉两个互相重度干扰的低 `g` 单元，会让它们的邻居 `g` 上升，部分甚至完全补偿删除损失。
**结论：冻结 `g` 的不动点会提前停下**，真实重算后仍存在改进交换（本项目 Q2 有 53 个）。

**检查动作**：证书阶段**逐候选真实重算**，不用冻结代理。若真实重算发现改进交换，
说明交换不该只当"证书"，而应当**作为一个搜索阶段纳入流水线**。（案例 C5）

### 5.3 证书必须与验收同判据

用代理口径（压缩时点/降采样/粗档位）出证书，会在定稿解上报出一堆"改进"，
全是被验收口径回退掉的那些。**证书判据 ≡ 验收判据**，否则证书无意义。（案例 C7）

## 6. 代理口径必须以验收口径收口

**规则**：任何为提速引入的代理（对称性压缩、降采样、粗求积、子集评估、缓存的 `g`）都有
**成立前提**。搜索过程本身常常**破坏**这个前提。

**触发**：用了任何"等价但更快"的算法。尤其是基于**对称性**的压缩。

**典型失效**：对称性压缩只在个体集合关于对称轴对称时才是恒等式，而**取舍与交换会破坏对称性**
——压缩误差从 0.055% 涨到 0.075%，足以让代理口径下"达标"的方案在上报口径下变成不达标
（本项目出现过上报 59.9883 < 60 的方案，被硬校验拦下）。

**检查动作**：

1. 写下代理的成立前提，然后问：**搜索会不会破坏它？**
2. 会破坏 → **搜索过程直接用验收口径**，让搜索判据 ≡ 验收判据；
3. **不要靠"调大代理侧余量"兜底**。余量要覆盖代理偏差就得设得很大，而最优解往往本身就
   贴着约束（本项目不动点解只高出额定 0.062%），余量提到 0.15% 就把搜索完全堵死；
4. 流水线各段的**求积档位/离散档位必须一致**，并写成硬断言。粗档位上"刚好达标"的方案
   到细档位会掉出可行域。**取舍档位必须等于上报档位。**（案例 C6）

## 7. 基线未优化到位 ⇒ 改进量被系统性高估

**规则**：报告"方案 B 比方案 A 好 X%"之前，确认 **A 本身已经优化到位**。
基线欠优化时，X 里混进了"A 还没搜完"的部分。

**触发**：任何跨方案比较、任何"放开约束后提升了多少"的结论。多问题竞赛里，
Q3 相对 Q2 的提升几乎必然踩这条。

**本项目实测**：Q2 重新搜索后自身涨了 0.86%，Q3 涨了 0.42%，于是"Q3 相对 Q2 的优势"
从 +0.567% 缩到 +0.134%。**Q3 没变差，是基线变强了。**

**检查动作**：

1. 冻结任何"相对提升"数字之前，对基线**再跑一轮同等强度的搜索**；
2. 两个方案必须用**同一档位、同一取舍流程、同一验收口径**评价；
3. 论文里写提升幅度时，注明基线的优化程度（"基线经同等强度搜索后"）。

（案例 C9）

## 8. 嵌套模型族的单调性自检

**规则**：若模型族 B **包含** A 作为退化情形（A 的参数是 B 的一个取值），则族内最优
**必然** `J*_B ≥ J*_A`。实测出"B 更差"在数学上不可能，只能说明**搜索没做好**。

**触发**：分区 vs 不分区、K 段 vs K−1 段、放开约束 vs 不放开、异构 vs 同构。

**检查动作**：

1. 建立包含关系后，把 `J*_B ≥ J*_A` 写成一条**自检断言**；
2. 断言不过 → 回去查搜索，**不要**把它写成"B 不如 A"的结论；
3. 论文里主动写出这条包含关系，它同时是一致性检查和一个可验证的正确性论据；
4. 换了外生设定（分布假设、场景）后 B 不再占优，只说明**该设定下需重新优化 B 的参数**，
   不表示"B 的最优不如 A"。（案例 C11）

## 9. 一阶估计必须包含反馈项

**规则**：用一阶/线性化构造改进方向时，检查是否漏掉了**目标对决策变量的反馈**。
漏掉反馈的构造会给出错误方向，且错得不明显。

**本项目实测**：容量守恒的一阶构造把 `g` 当常数，忽略了"抬高会加重遮挡"这个 `∂g/∂h < 0`
的效应——而这恰恰是整个问题的物理核心。**实测反馈吃掉一阶估计的 42%。**

**检查动作**：

1. 写出一阶构造时，逐项检查"这个量真的与决策变量无关吗"；
2. 有反馈的量 → 改用**有限差分实测灵敏度**，并据此限制步长；
3. 构造出的方向必须**实测验证**，一阶估计只用来选方向，不用来报数字。

（案例 C12）

## 10. 网格搜索的收敛证据

**规则**：网格扫描本身是正当的优化方法——目标函数含个数跳变、边界掉解与可行性边界时
大概率不光滑，换梯度法或群智能**不会自动更可信**。真正缺的不是"高级算法"，
而是**网格细化与最优点稳定性证据**。

**触发**：用了任何形式的网格/枚举搜索。

**检查动作**：

1. **细化的中心必须跟随当前最优。** 若第 k 层发现最优点移到了边缘，第 k+1 层还在老中心
   邻域探点，那么"第 k+1 层无变化"**不构成收敛证据**。本项目正是这样错过了真正的最优点，
   重新围绕当前最优展开后目标值 +0.455%；
2. 逐层记录 (层号, 中心, 步长, 最优点, 目标值)，最优点连续两层不动才算收敛；
3. 多个连续变量互相影响时用**坐标轮换**迭代到目标值不再明显变化，
   避免"先锁一个变量、把其余精修到极致、最后发现锁错了"；
4. 不要把"没用群智能算法"写成缺陷并在论文里道歉——补收敛证据即可。

（案例 C8）

## 11. 搜索策略本身的两条反直觉

### 11.1 扩大动作集不保证结果更好

贪心有路径依赖。本项目加入"只删不放回"动作后，Q2 反而从 0.543060 退到 0.542914——
纯删除单步降幅大，贪心去拿它却提前耗光了能量余量。

**做法**：把**动作集与判据都当作重启维度**，多变体各跑一遍取最好者，并保存对比轨迹。
不要假设"动作更多 = 结果更好"。（案例 C5）

### 11.2 判据先于数字定死

比较两个方案族之前，**先写死换方案的门槛**（例如"E/A 提升 > 0.10% 才换"），再看数字。
否则事后总能为任一结果找到理由。

本项目据此保留了原方案：粗档筛选显示多分段 +0.310%，但搬进交付框架后两个多分段方案
**均不可行**（满负荷跌破额定）——粗档筛选的基准本身就劣于已交付方案，不能据此换方案。

**推论**：**粗档筛选的结论必须在交付档位复核后才能采信。** 筛选阶段的基准若劣于已交付方案，
该筛选的相对结论对交付无效。（案例 C13）

## 12. 验证的层级：内部自洽 ≠ 正确

**规则**：区分两类验证，论文里也要分开写。

| 类型 | 能证明什么 | 不能证明什么 |
|---|---|---|
| **内部自洽检验**（收敛研究、极限对拍、守恒检查、不动点、单调性） | 代码做了设计者想做的事 | 设计本身符合题意 |
| **独立方法对拍**（原理不同的第二套算法重算同一个量） | 收敛到的值是对的 | —— |

**关键认知**：**求积/离散收敛检验不能替代独立方法对拍。**
收敛曲线只能说明"细化后不再变"，说明不了"**收敛到的值偏了**"。

**检查动作**：

1. 对**最重的 1–2 个分量**，各用一套**原理不同**的算法重算（例：网格采样+求交 ↔ 多边形布尔
   解析面积；确定性求积 ↔ 蒙特卡罗）；
2. 分层抽样若干实例 + 若干极端情形，报告逐例差值的 **RMS、符号分布、区间**；
3. **符号检验**：差值若 35/36 同号（`p ≈ 1e-9`），那是**系统偏差**不是随机误差，必须定位机理；
4. **发现系统偏差要如实报告，不要修掉不提。** 本项目报告了 `10⁻³` 量级的系统正偏
   （相对偏差中位 +0.060%，最大出现在"大尺寸 + 极端角度"，与"求积对间断被积函数有偏"的
   机理吻合）。它比任何一项模型假设的影响都小一个数量级，不改变任何结论——
   但报告它本身证明了验证体系的有效性；
5. **精度标注分两层**：区分"给定模型下的数值解，数值误差 `10⁻⁴`"与"模型不确定性 `10⁻²`"。
   结论解释中不得暗示第四位小数有工程意义。

（案例 C14）

## 12.1 敏感性分析禁止用自制抽样代理

**规则**：跨方案比较的敏感性分析**必须用全样本**，不能用自制的分箱/代表点代理。

**本项目失效实例**：按 `(r, θ)` 分箱各取一个代表点。个体在平面上均匀分布时，
外圈箱内个体多得多，**等权分箱系统性抬高内区权重**；而两个待比较方案的剖面恰在外区不同，
该偏差对二者**不等量**，跨方案比较因此失效——探针版给出 Q3 比 Q2 差 0.903%，
全样本给出 **+0.567%，符号相反**。

**检查动作**：

1. 任何分箱/抽样代理，先问"**箱内个体数是否均衡**"；
2. 不均衡 → 要么按箱内个数加权，要么直接用全样本；
3. **跨方案比较一律用全样本**，代理只允许用于单方案的粗筛；
4. 敏感性结论用**区间表述**，不要挑一个端点叫"最保守"——
   本项目曾把三者的**最小**差值写成"最保守日面下的结果"，而它恰好出现在**最不保守**的设定上。
   两个方案之比的变化与"设定保守程度"之间**没有单调关系**。

（案例 C15）

## 13. 打包前硬门（`audit.py` 模式）

**规则**：把上述检查写成**可执行断言**，任一不过**拒绝打包**。人工 checklist 会漏，硬门不会。

最小硬门集合（按本项目实践）：

```text
[ ] 三段流水线的求积/离散档位一致
[ ] 交换改进门槛 ≥ 交付门槛
[ ] 交付结果文件 == 流水线最后一段的输出（哈希比对，不是"看起来一样"）
[ ] 最终方案的交换证书为 0 个改进交换（用验收口径）
[ ] 上报指标 ≥ 题面额定值（用验收口径，不是代理口径）
[ ] 论文正文出现的每个数字都能在结果文件里找到
[ ] 题面符号对账表 12/12 通过
```

**配套纪律**：

- 每一项数值改动，**原始数据 + 生成脚本**一并入包；
- 旧日志**保留并附事后更正，不回改**——回改会让"当时是怎么想的"永久丢失；
- 交付包附 `CHANGELOG.md`，记录"旧版的问题 → 新版做法 → 验证"，
  它同时是复盘材料和评审信任来源。
