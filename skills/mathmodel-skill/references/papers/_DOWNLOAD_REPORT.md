## 2. 错在哪里

原报告把第四行那批 58 份记为国赛论文，依据只有目录名。**「A-F 题号齐全」这句话本身就是它不是国赛的证据**：国赛本科组只设 A/B/C，专科组只设 D/E，不设 F 题。

这批文件占进入统计的 59 份中的 58 份。由此烘焙出的分位数不能代表国赛，已随 `empirical.json` 一并撤回。

原报告的「来源抽检」一节曾抽查 3 份官方展廊文件的首页确认年份 —— 但抽检对象全部来自展廊那 32 份，**从未抽检占绝大多数的那 58 份**。抽检覆盖面与样本构成不匹配，是这个错误能一路传下来的原因。

## 3. 教训

- 来源标签必须核验到一手出处，目录名和文件名不构成证据。
- 抽检应当覆盖**占样本量最大**的来源，而不是最容易打开的那个。
- 统计产物里出现与赛制不符的类别（如国赛的 F 题），应当作为来源污染的告警，而不是照单记录。

## 4. 重新下载

`scripts/download_cumcm_papers.py` 是维护脚本，不在比赛运行时调用。当前实现有三个已知缺口，重建前需先修：

1. 只登记 2023/2024 展廊列表页，缺 2025；
2. 2023 列表页为「查看更多」懒加载，脚本未展开分页，会漏抓；2024/2025 为按题号分 tab 的结构，需分别处理；
3. 无题号过滤入口。题号可从标题解析（`extract_code` 已支持 `（B226）` 格式），应在下载前按题号筛选，避免下载不需要的 D/E。

运行前先安装 `scripts/requirements-maintenance.txt`，并确认站点结构与来源使用范围：

```bash
python scripts/download_cumcm_papers.py --papers-dir /path/to/cumcm-papers --years 2023 2024
```

不要把原始论文 PDF 提交到本仓库（`.gitignore` 已排除 `references/papers/*.pdf`）。
