# 仅题面启动与文献证据门禁

用于用户只提供竞赛题面和附件，或只提供部分参考文献/优秀论文，但要求完成分析、
建模、求解或论文时。用户文献只作为种子与补充证据，不能关闭主动检索。目标是防止
模型只凭题目表层关键词或有限文献套用常见方法并过早开始写稿。

## 1. 输入包先分类

开始前盘点并区分：

| 类型 | 作用 |
|---|---|
| 官方题面 | 定义任务、约束和交付要求 |
| 数据附件 | 决定可计算内容；缺失时必须索取，不能用文献代替 |
| 用户提供的技术文献/标准 | 候选理论、参数和方法证据 |
| 用户提供的优秀论文 | 结构、证据密度和评委阅读路径校准 |
| 自动检索文献 | 补足理论、方法、参数、验证和创新比较 |

优秀论文不是默认技术权威。若其中出现关键模型、参数或结论，应追溯其原始论文、教材、
标准或官方来源，不能只引用优秀论文本身。

## 2. 禁止过早写稿

仅题面输入时，在以下产物完成前，不得开始摘要、正文或“最终模型”写作：

1. 题面完整读取并完成多遍精读；
2. 附件清单与数据 schema 扫描；
3. 全部子问题的输入、输出、约束、目标和依赖卡片；
4. 知识缺口与外部主张清单；
5. 分主题文献检索计划；
6. 至少一轮自动检索、去重和来源核验；
7. 文献—主张映射；
8. 基于题面、数据与文献共同形成的候选模型比较。

可以在此期间写分析报告和候选路线，不得把候选路线直接包装成论文定稿。

## 3. 题面深读与知识缺口

沿用 Stage 2 的三遍精读，并额外建立知识缺口表：

| 子问题 | 题面已给事实 | 数据可直接计算 | 需要外部证据 | 不能由文献替代的信息 |
|---|---|---|---|---|
| Qi | 参数、约束、定义 | 统计量、字段、范围 | 物理机制、标准模型、参数来源、验证方法 | 缺失附件、真实标签、题面专有条件 |

不得用论文中的常见假设覆盖题目尚未说明的关键事实。文献只能支持模型与参数选择，不能
凭空补出题目没有提供的样本、标签或测量值。

## 4. 文献问题矩阵

每个子问题至少检查以下证据类别是否适用：

1. **领域机制与标准**：官方标准、定义、物理/业务机制；
2. **基础模型**：原始论文、权威教材或公认理论；
3. **数据和参数**：材料常数、经验范围、测量方法、数据生成机制；
4. **候选方法**：能够解决同一任务的结构性不同方案；
5. **求解与诊断**：优化器、收敛、残差、稳健性和不确定性方法；
6. **应用案例**：相近数据、尺度或工程场景中的实际用法；
7. **创新比较**：若要声称本题特化设计，检索最接近的已有方法；
8. **优秀论文校准**：只检查结构、展开深度和证据顺序，不复制内容。

按“需要支撑的主张”组织检索，不以凑够固定篇数为目标。

## 5. 自动检索深度

无论用户没有提供文献，还是只提供了部分文献，都先做证据覆盖审计。用户文献作为
种子词、引文网络和已知方向输入；随后自动调用 `paper-search-pro` 的 agent/headless
模式补齐缺口，并根据问题选择检索深度：

- **Quick**：时间极紧、模型高度标准、外部参数很少；
- **Standard（默认）**：领域机制、材料参数、专业模型或创新比较会影响选型；
- **Deep**：用户明确要求深度调研，或不同文献结论明显冲突；
- **Audit**：只有系统综述类任务且用户确认成本后使用。

技术问题优先采用原始研究、官方标准、权威数据库和正式文档。综述适合发现术语和引用
网络，但核心公式、参数和创新归属应尽量回到原始来源。

中文题目不等于只检索中文文献。默认根据领域构造中英文术语；标准、国内业务规则和
本土统计口径优先补中文来源，基础科学和通用算法同时检索英文来源。

### 5.1 部分文献输入不关闭检索

用户上传部分文献后，至少执行一次补充检索：

1. 从题面独立提取关键词，不只沿用用户文献的术语；
2. 从种子文献提取同义词、标准号、作者关键词和引文链；
3. 对照文献问题矩阵查找尚未覆盖的机制、参数、候选模型和验证方法；
4. 时间紧时至少执行 Quick 缺口检索；专业机制或创新比较影响选型时仍执行 Standard；
5. 用户文献与自动检索文献使用同一质量和适用性标准，不因来源是用户上传就自动采纳。

不得回复“已有文献足够”后直接写稿，除非覆盖审计证明所有核心主张已有核验来源，且仍
完成一轮独立检索用于发现遗漏和反例。

## 6. 必须形成的证据产物

建议在项目中生成：

- `reports/input_inventory.md`：题面、附件、用户文献和优秀论文分类；
- `reports/problem_decomposition.md`：多遍精读与子问题卡片；
- `reports/literature_search_plan.md`：每个 Qi 的中英文查询式和证据类别；
- `reports/literature_search_trace.md`：题面触发词、实际查询式、数据库和检索时间；
- `results/literature_retrieval_all.csv`：全部原始检索命中及地址；
- `results/literature_shortlist.csv`：筛选后的候选/采用文献及理由；
- `reports/literature_claim_map.md`：主张—来源—使用位置—核验状态；
- `reports/refs_verified.json`：题名、作者、年份、DOI/标准号和核验结果；
- `paper/ref.bib` 或比赛对应的 BibTeX 文件。

文献—主张映射至少包含：

```text
claim_id
要支撑的主张
主张类型（机制/公式/参数/方法/比较/局限）
来源
是否打开原文或官方页面核验
计划写入的章节
允许的表述强度
```

每个会影响模型选择、参数范围或创新归属的外部主张都必须能定位到来源；背景常识不需要
为了篇数重复堆引文。

### 6.1 检索过程必须主动向用户透明报告

每轮检索结束后，不等待用户追问，先报告：

1. 从题目哪个小问、句子或数据特征提取了哪些关键词；
2. 实际使用的中文关键词、英文关键词、同义词和组合查询式；
3. 检索了哪些平台或来源，如 OpenAlex、Semantic Scholar、Crossref、arXiv、PubMed、
   NSSD、官方标准网站或机构数据库；
4. 各平台命中数、去重数、筛选数和无法访问的范围；
5. 下一轮为何需要扩展、收缩或更换关键词。

所有原始命中写入完整清单；所有进入高质量短名单、候选模型证据或最终引用池的文献，
必须逐篇向用户报告：

| 字段 | 要求 |
|---|---|
| 对应小问/主张 | 说明它解决哪个证据缺口 |
| 题面触发词 | 来自题目、附件字段或机制需求 |
| 实际检索关键词 | 给出中英文词和关键组合 |
| 文献题名、作者、年份、来源 | 不得只写简称 |
| 检索平台 | 说明从哪里找到 |
| 文献地址 | 提供已核验的 DOI、官方落地页或稳定URL |
| 质量理由 | 原始研究/标准/权威文档、同行评审、相关性、适用尺度等 |
| 使用理由 | 支撑公式、参数、候选模型、验证、局限或创新比较 |
| 使用状态 | `adopted | candidate | rejected`，拒绝时写原因 |
| 可访问性 | 全文、摘要/元数据、付费墙或无法打开 |

地址不得根据 DOI 格式猜测；必须实际核验页面能对应正确题名和作者。若文献较多，可以
分批在对话中报告，并同时交付完整 Markdown/CSV 清单，但不得只给 BibTeX 而省略检索
关键词、来源和采用理由。

“找到的全部文献”分两层处理：

- 所有数据库原始命中：完整保存到 `literature_retrieval_all.csv`，含地址和筛选状态；
- 所有高质量短名单与采用文献：在对话和报告中逐篇说明上述字段。

这样既保留完整透明性，也避免把大量低相关、重复或明显不合格的原始命中混入论文引用池。

### 6.2 短名单形成后执行质量门禁

检索透明不等于证据充分。短名单完成后读取 `literature_quality_control.md`，继续检查
来源适配、全文访问深度、文献冲突、参数来源、时效/更正状态、检索饱和和引用落点。
这些检查未完成时，`literature_bootstrap.status` 不得直接写为 `pass`。

## 7. 文献门禁状态

写入 `decision_log.stages.2.literature_bootstrap`：

```json
{
  "input_mode": "problem_only | problem_plus_user_literature",
  "search_tier": "quick | standard | deep | audit",
  "status": "pass | conditional | block",
  "query_plan_path": "reports/literature_search_plan.md",
  "search_trace_path": "reports/literature_search_trace.md",
  "retrieval_all_path": "results/literature_retrieval_all.csv",
  "shortlist_path": "results/literature_shortlist.csv",
  "claim_map_path": "reports/literature_claim_map.md",
  "verified_sources_path": "reports/refs_verified.json",
  "quality_gate_path": "results/literature_quality_assessment.csv",
  "missing_evidence": [],
  "user_documents_needed": []
}
```

- `pass`：核心选型、参数和验证主张均有足够来源；
- `conditional`：可以继续数学探索，但部分主张必须保持弱表述，且不能写入终稿；
- `block`：网络/工具不可用，或关键领域证据缺失到足以改变模型路线。

Stage 3 可以在 `conditional` 下生成候选和 toy demo，但不得锁定依赖缺失证据的最终模型；
`block` 时停止论文写作并输出精确的缺失文献清单。

## 8. 用户提供文献时的处理

用户提供或后续补充文献、标准或优秀论文时，均视为种子文献而非封闭文献集：

1. 不推翻已有检索，也不停止主动补充检索；先去重并分类；
2. 检查它补的是哪项 `missing_evidence`；
3. 核验题名、作者、年份、DOI/标准号和适用条件；
4. 技术文献进入主张映射；
5. 优秀论文进入结构校准记录；
6. 若新证据改变模型路线，回到 Stage 3 定向重评，不直接在论文中换模型名称。

用户自己找文献最有价值的场景是：付费墙全文、中文专业数据库、行业标准、题目组织方
资料以及确切的优秀论文。一般英文论文和公开元数据不需要用户每次手工包办。

## 9. 检索失败时的行为

不得在检索失败后默默依靠记忆继续写论文。应报告：

- 哪些数据库或工具不可用；
- 已完成到哪一步；
- 哪些关键主张没有来源；
- 这会阻塞模型选型、参数设定还是只影响背景；
- 用户需要补充的最小文献类别和建议检索式。

能从题面严格推导的数学内容可以继续作为探索稿，但必须标记为未通过文献门禁，不能冒充
可提交论文。

## 10. 推荐的仅题面启动指令

用户下次只需上传题面和全部数据附件，并说明：

> 使用 `$26math` 以“题面与种子文献启动”模式工作。无论我是否上传部分文献，都要先
> 完整读题、扫描附件、建立知识缺口和文献检索矩阵，并主动补充必要的中英文高质量
> 文献。逐轮告诉我题面触发词、实际检索关键词、检索平台、文献链接和采用理由；全部
> 原始命中保存清单，所有高质量短名单逐篇报告。在文献—主张映射和候选模型比较完成前
> 不要写论文正文。先汇报题目理解、文献缺口、候选路线和仍需我补充的资料，再进入求解。

无需预先上传大量文献；若有行业标准、付费全文或优秀论文，可同时提供作为增强材料。
