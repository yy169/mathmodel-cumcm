# 多轮改稿案例时间线与反例库

当同一竞赛论文已经经历模型更新、篇幅扩展、图表重构、摘要反复调整、评委视角
重排和最终微调时读取本文件。它记录一次完整改稿链中“为什么改、改后发生什么、
哪些决定后来被撤回”的经验，用于防止只记住最终稿而忘记形成最终稿的原因。

案例数字只用于说明修改类型和风险，不构成其他题目的结果、页数或图数目标。

## 1. 必须审计上一对话，而不只看最终答复

接续任务时，若 harness 能读取上一任务/线程：

1. 分页读取完整历史，不只读取最近 10 个回合或最终摘要。
2. 提取用户确认的方向、被撤回的方向、失败执行、文件修改和最终交付。
3. 把对话记录与当前文件、时间戳、备份、结果 JSON 和编译日志交叉验证。
4. 将“当时声称完成但后来被推翻”的结论标记为历史状态，不能继续沿用。

若无法读取旧对话，则检查导出的会话记录、reports、备份文件、README、状态事件和
旧 PDF。对话是决策证据，不是技术真值；最终仍以真实文件和运行结果核验。

## 2. 阶段 A：过早把合规当成完成

早期版本约 15–16 页，已经具备模型、真实结果、引用、匿名和可编译 PDF，因此一度
被判为“完整论文与支撑材料已完成”。

后来逐页比较发现：

- 技术正文只有约 12 页，核心模型—结果—检验链约 8 页；
- 代码已经实现预处理、频域初值、联合反演、消融、Bootstrap 和参数相关性，
  论文却只报告了最终数字；
- 5 张复合图承担过多任务；
- “未超过 30 页”只证明合规，不能证明竞争力。

**经验：** 在宣布最终完成前必须执行篇幅与证据密度审计。编译成功、页数合规、
匿名通过只是提交门槛，不是内容完成门槛。

## 3. 阶段 B：权威结果源发生迁移

最初论文采用全谱反演结果，例如：

- SiC 约 `7.3182 μm`；
- Si 约 `3.3982 μm`；
- 跨工作带比较得到较大的 RMSE 改善。

后续发现强吸收区的大反射幅值在统一平方误差中压过透明区条纹相位，因此新增
“全谱材料预拟合—稳定工作带相位精修”：

- SiC 首选结果更新为约 `7.4325 μm`；
- Si 首选结果更新为约 `3.4162 μm`；
- 双/多光束比较改为同一工作带、同一先验和同一优化器，改善率更新为约 `26.78%`；
- 原全谱结果不删除，改为模型形式敏感性证据。

**经验：**

1. 新模型不是简单覆盖旧数字，而是改变“哪一个结果是 authoritative”。
2. 必须同步摘要、正文、表格、README、AI 披露、结果报告、运行日志和提交包。
3. 旧结果若仍有解释价值，应明确降级为基线或模型形式不确定性，不能静默消失。
4. 不能比较不同工作带或不同约束下的 RMSE 后声称模型本身改善。

## 4. 阶段 C：先诊断页数问题，再扩展证据

用户明确要求“先别着急改论文，分析为什么没有优秀论文的页数”。正确处理是暂停
编辑，拆分：

- 总页数；
- 摘要与前置页；
- 有效技术正文；
- 核心技术页；
- 参考文献；
- 附录和代码。

诊断表明问题不是文字少，而是代码完成度显著高于论文展示度。随后才制定扩写蓝图。

**经验：** 用户要求先诊断时，不得边诊断边偷偷改稿。先给出证据缺口、逐页任务和
禁止填充内容，得到方向确认后再实施。

## 5. 阶段 D：图表从装饰转为证据体系

原版本约 5 张复合图，存在：

- 拟合与残差共用双纵轴；
- 不同材料绝对 RMSE 放在同一柱状图；
- 子频段、相关矩阵和其他诊断塞在同一图；
- 多光束判断只有数字，没有峰形、残差和谐波分布。

重构流程：

1. 先盘点缺失证据；
2. 在预览目录生成候选图；
3. 生成联系表供用户确认；
4. 用户确认后才覆盖正式图和修改论文；
5. 正式图由真实附件重跑，保存数值快照和 SHA-256；
6. 逐页渲染终审。

论文由约 16 页自然扩展到约 24 页，图表由 5 张复合图重构为 13 张单任务图。

**经验：** 页数增长应来自证据链，而不是图片配额。先预览再采用能避免风格不满意时
污染正式论文。图表完成门禁已经固化在 `figure_evidence_system.md`。

## 6. 阶段 E：摘要并非越短越好

摘要经历了三次典型变化：

1. 初版包含大量 RMSE、BIC、区间和频段数字，信息过密；
2. 按优秀论文样式压缩为“对于问题一/二/三”，但一度删得过多，页面和必要信息不足；
3. 补回复折射率、双角共享、FFT 初值作用、同条件消融和可靠性边界，使摘要自然占满
   一页，而不是通过字号或空白填充。

最终正文稳定后，又只微调第一段：从 Lorentz、AsLS、FFT 等工具清单改为“信息分工、
双角共享约束、多光束适用性判别”的核心矛盾。

**经验：**

- 用户要求“只改摘要”时严格限制修改范围；
- 摘要压缩不能删除模型、结果和验证三类必要信息；
- 页面是否填满只能作为视觉检查，不能成为增加重复句的理由；
- 正文未稳定时不要反复定稿摘要；
- 每次摘要变动都要保留备份并重新渲染第一页。

## 7. 阶段 F：评委视角结构重构

图表和技术结果稳定后，进行中等幅度重排：

- 新增“三难点—三策略—统一求解”流程图；
- 每问开头增加“本问结论”；
- 增加核心结果总表；
- 问题三改为“必要条件 → Airy 模型 → 公平消融 → 谐波旁证”；
- 创新固定为“2 个核心创新 + 1 个求解设计亮点”；
- 完整预处理、FFT、零分布、Q--Q/ACF 和相关矩阵下沉附录；
- 模型优点由多条压缩为 3 条，具体局限和负面结果保留。

页数由 24 页变为 23 页，原因是删除重复图内标题和修复表格布局，不是删技术。

**经验：** 结构重构的衡量标准是评委恢复主线所需时间，不是字数变化。正文必须保留
基线、消融、不确定性、工程敏感性和负面结果，不能把所有高级检验都移走。

## 8. 阶段 G：创新话术和关键词微调

求解亮点最初写有：

> 不在缺少运行时间和收敛率对照时夸大为独立创新算法。

虽然态度正确，但属于对审稿人的元话语。最终改为只陈述可验证事实：条件最优标定和
外层搜索维数降低。

关键词最初全部是“非线性最小二乘、参数估计、模型拟合、敏感性分析”等通用词；
外部建议又倾向全部改为领域对象词。最终采用“对象/任务 + 建模术语”的混合写法，
并运行关键词检查。

**经验：**

- 不把克制态度写成辩论句，直接报告证据；
- 不写未经对照验证的“提高数值稳定性”；
- 关键词既要让人知道论文研究什么，也必须包含可识别的模型、算法或检验术语。

## 9. 容易被旧对话暴露的操作问题

### 9.1 PDF 被占用

主 PDF 被预览程序占用时，覆盖失败。不得继续声称原文件已更新；应保存新文件名，
记录 authoritative PDF 路径，并在交付说明中区分旧版和新版。

### 9.2 工作目录和 Git 状态错位

新线程默认目录可能不包含论文；实际项目位于上一任务目录。项目本身可能不是 Git
仓库，而默认目录存在无关 Git 仓库。必须先定位实际项目，不能报告无关 Git 状态。

### 9.3 结果和报告陈旧

正文更新后，旧 README、AI 详情、质量报告和 ZIP 仍可能保存旧页数、旧图数或旧结果。
最终提交前应在支撑材料 staging 目录中搜索旧数字、旧文件名和历史页数。

### 9.4 一键入口依赖环境

`run_all.ps1` 曾依赖硬编码的本机 Python 路径，随后改为系统 Python，又因缺少 SciPy
失败。最终做法是：

- 自动发现满足依赖的解释器；
- 优先加载项目本地依赖；
- 在无预设 `PYTHONPATH` 下测试；
- README 明确 `pip install -r requirements.txt`。

### 9.5 中文 AI 披露 PDF

ReportLab 初版使用 CID 字体和普通字符串表格，出现字体或中文换行问题。最终改用
可用中文字体、把单元格包装为 `Paragraph`、启用 CJK 换行并逐页渲染检查。

### 9.6 匿名检查误报

严格扫描发现 `University`，实际来自 `Cambridge University Press`。必须定位原文后
才能豁免；不能看到误报就关闭匿名检查。

### 9.7 Skill 验证环境

验证脚本可能因缺少 PyYAML 或 Windows 默认 GBK 读取 UTF-8 失败。应更换带 PyYAML 的
解释器并设置 UTF-8，再实际运行 `quick_validate.py`；不得在验证失败时声称 Skill 有效。

## 10. 曾经考虑但最终拒绝的改法

- 为接近优秀论文而强行写满 30 页；
- 机械删除 15%–20%；
- 把所有完整诊断移出正文；
- 把闭式内环直接包装成强创新；
- 用不同工作带的 RMSE 证明模型改善；
- 只展示显著 p 值而隐去边缘或不显著结果；
- 关键词全部使用领域对象词，或全部使用泛化建模词；
- 因“检验很多”就在没有版面压力时删除有工程意义的敏感性；
- 正文稳定后继续进行全局重写。

## 11. 可复用的修改阶段

以后处理类似论文，按以下顺序：

1. 独立技术求解与初稿；
2. 权威结果源和跨文件一致性锁定；
3. 篇幅/证据密度诊断；
4. 图表预览与证据体系重构；
5. 技术正文扩展；
6. 评委视角结构重排；
7. 摘要、关键词和创新话术微调；
8. 语言终审与 LaTeX 预检；
9. 完整对话/修改日志回看；
10. 提交包同步、旧数字搜索和权威文件冻结。

每个阶段完成后记录哪些章节被冻结。不得跳过第 9 步，只根据最终 PDF 猜测此前决策。

## 12. 阶段 H：终稿缺陷校准与澄清性微调

在 23 页终稿已通过结构、技术和视觉门禁后，用户追问“为何不能满分”，最初把
“没有独立仪器厚度真值、闭式内环缺少效率对照、参数相关性”并列为剩余不足。
复核后必须拆开：

- 附件光谱是真实测量数据；缺少的只是题目未提供的外部厚度真值。两篇参考优秀论文
  同样没有该真值，因此它是理想科研证据上限，不是当前稿可通过写作修复的相对缺陷；
- 闭式内环已经数学上实现条件最优并把外层从 7 维降到 3 维。缺少时间和收敛率对照
  只限制其不能宣称独立算法创新，不影响它作为求解设计亮点；
- 厚度与载流子参数相关，但厚度在双角、峰谷基线、子频段和条件局部剖面下稳定。
  应限制伴随参数解释，而不是笼统声称厚度不可靠。

最终只做三项澄清性修改：

1. 关键词由工具词改为“外延层厚度、相位优先、双角联合反演、多光束干涉、模型选择”；
2. 删除求解亮点中重复的“7 维降至 3 维”，只保留 4 个线性标定参数不进入外层搜索的事实；
3. 局限段先报告厚度稳定性，再把单一极小值限定为“固定材料参数的局部剖面”，并把
   `N_1,N_2` 限定为光学等效参数。

模型、结果、图表和检验全部冻结。综合评分只在阅读和误读风险维度小幅提高，不能因
文字变好而虚增技术证据分。

执行中还暴露两个可复用操作规则：

- PowerShell 多行替换在 here-string 解析阶段失败时，先确认目标文件未变化，再改用
  精确匹配计数的 UTF-8 脚本；
- AI 披露生成因默认 Python 缺少 ReportLab 中止时，识别已发生的部分修改，改用项目
  本地依赖并使同步脚本可幂等重试，不能假定失败前没有任何写入。

最终重新编译为 23 页，核验摘要页和第 16--18 页，同步 AI 日期、决策日志、预检报告、
MANIFEST、支撑 ZIP 和新的权威 PDF 文件名。

**经验：** 成熟终稿的最后优化通常不是继续补技术，而是把“目标结论稳定、伴随参数
受限、求解亮点证据等级、题目数据上限”写到恰好与现有证据一致。剩余差距若只能通过
新数据、新仪器或独立性能实验解决，应停止改稿。

## 13. 仅题面启动时的文献缺口风险

本次高质量终稿不仅依赖模型和代码，也受益于用户预先提供的专业文献与优秀论文。若下一次
只上传题面，旧流程中的“需要文献时调用检索”仍可能被弱执行解释为可选步骤，导致模型只
抓题目关键词、快速套用常见方法并过早写论文。

因此增加强制的仅题面启动门禁：

1. 题面与数据附件先完整盘点；缺数据附件时必须索取，文献不能代替数据；
2. 三遍精读后建立知识缺口和文献问题矩阵；
3. 没有用户文献时默认自动执行 Standard 级中英文检索；
4. 形成检索计划、核验结果和文献—主张映射；
5. Stage 3 在门禁通过前不得锁定依赖外部证据的最终模型；
6. 摘要和正文不得先于证据地图开始；
7. 优秀论文只用于结构校准，关键技术回溯原始论文、标准或官方来源；
8. 检索失败时报告最小缺失资料，不得默默依靠记忆继续写稿。

## 14. 阶段 I：成熟终稿的图表可读性与“AI 模板感”复核

23 页终稿的技术、结构和证据均已冻结后，用户在实际 PDF 中发现图 2 的图内总标题与
全局图例重叠，并指出小插图文字过小。进一步联系表审计发现，这不是单图问题：

- 多数复合图同时使用 `suptitle(y=1.01/1.02)`、`tight_layout()` 和图例，存在潜在碰撞；
- 全局字号 9.5 pt 在源图中正常，但按正文宽度缩放后偏小；
- 图 2 的残差 inset 使用 7 pt 标题和 6 pt 刻度，正文中不可可靠辨读；
- 图 8、图 9、图 10 存在 7.5 pt 局部图例；
- 若干图内总标题重复 LaTeX 图注，且直接写“残差不是白噪声”“RMSE 降低”等结论，
  增加模板化和自我评价感；
- 浅色填充本身并非缺陷，但高透明度工作带、区间和材料层同时出现时，会削弱主证据层级。

最终处理：

1. 不改任何模型、数据、结果和证据位置，只修改统一制图脚本；
2. 先在独立预览目录重跑 14 张图和联系表，确认后再备份并覆盖正式图；
3. 图 2 改为四组“主光谱 + 独立残差条带”，取消小 inset；
4. 删除与图注重复的所有图内总标题，子图标题只保留对象和统计量；
5. 复合图改用共享图例或直接数值框，取消 6--7.5 pt 微型标注；
6. 放大统一字号和线宽，字体优先使用 Microsoft YaHei，不把 SimHei 作为默认风格；
7. 主曲线使用深色，浅色仅以低透明度承担工作带、区间和材料层语义；
8. 正式重跑、一致性检查、XeLaTeX 编译和逐页渲染全部重新执行。

图表增高使论文由 23 页变为 24 页。复核认为新增页数来自可读性和证据展开，而不是
空白填充；尝试缩小图 14 并未减少页数，故恢复原宽度，不为追回页数牺牲附录可读性。

**经验：**

- 高 DPI 不能补救正文缩放后的物理字号，必须按插图宽度估算；
- `suptitle + figure legend + tight_layout` 是复合图碰撞高风险组合；
- inset 只在缩放后仍可读时使用，否则改为嵌套网格；
- 降低“AI 味”应针对默认样式、重复标题、结论式图内话术和层级混乱，不能机械禁用
  浅色、列表或 Python；
- 成熟终稿仍可解冻视觉样式，但模型和数值继续冻结，且必须保留正式图备份和完整重跑；
- 预览、正式制图和全流水线不得无差别重复。先静态扫描，再只预览关键图，风格锁定后
  一次生成全部正式图，最后只执行一次全流水线；
- 每个阶段完成后立即同步计划状态。不能因计划仍显示“检查中”而让用户误以为长时间和
  额度消耗没有形成产物；报告剩余任务时必须区分“PDF 已完成”和“提交包尚未同步”。

用户不需要每次人工收集全部公开论文。最值得人工补充的是行业标准、付费全文、中文专业
数据库资料、题目组织方材料和指定优秀论文；公开英文文献与元数据由工作流主动检索。

后续进一步明确：用户即使上传了部分文献，这些文献也只是种子，不能关闭独立补充检索。
每轮必须主动说明题面触发词、中英文检索词、检索平台和命中筛选过程；所有原始命中保存
含地址的完整清单，所有高质量短名单与采用文献逐篇报告链接、质量理由、使用理由和状态。
若文献较多可分批汇报，但不得只交付 BibTeX 或只说“已查阅相关文献”。

**经验：** “用户没有上传文献”不是降低论文深度的理由，而是触发自动检索和暂停写稿的
信号。只有题面、数据、文献和候选模型证据四者闭环后，才进入真实求解和论文写作。

## 14. 文献透明之后仍需质量与引用落地

仅记录检索词、平台、链接和采用理由仍不足以保证论文质量。进一步增加：

- 来源类型必须与主张匹配，不能用高引用但条件不符的论文替代相关性；
- 仅元数据只能证明文献存在，摘要只能支持概括性判断，精确公式和参数原则上要求全文；
- 冲突文献按材料、样本、尺度、条件、假设和版本解释，不能多数投票；
- 每个外部参数建立数值、单位、条件、原文位置、换算和代码用途台账；
- 标准、法规、软件文档和动态数据核对当前版本，重点论文检查撤稿和更正；
- 使用检索饱和与边际新增证据作为停止依据，不按固定篇数，也不无限扩张；
- Stage 8 建立引用—主张审计，禁止段末堆引用、二手引用洗白和限定条件错配。

**经验：** 文献流程的完成标准不是“找到很多论文”，而是每个高影响主张都由访问深度、
适用条件和时效均匹配的来源支撑，并能准确落到论文句子、参数和代码中。

## 15. 图像生成必须区分程序制图与生成式图片

本次用户满意的图表重构实质上是 `publication_figures.py` 读取真实附件、结果 JSON 和
诊断输出后进行程序制图，并经过预览联系表、正式重跑、数值快照、一致性检查和逐页终审。
它不等同于普通文生图。

后续固化三类图像：

- A 级定量证据图：真实代码生成，可支撑拟合、残差、消融、区间和敏感性；
- B 级确定性示意图：TikZ/SVG/Matplotlib 等重绘，只支撑结构与机制；
- C 级生成式插图：只作非定量说明，不得承担任何数值结论。

用户上传喜欢的截图或参考图时，将其作为风格种子，提取字体、配色、线宽、留白、子图密度
和图例习惯，并记录采用/拒绝的风格元素；不复制参考图构图、数据和结论。风格一旦确认就
冻结，除非存在可读性或合规缺陷。

每个小问求解后即建立候选图和证据问题，不等 Stage 8 临时补图。正式图记录输入数据、
结果快照、脚本、命令、随机种子、样式、SHA-256、论文位置和 AI 使用状态，并主动向用户
说明每张图为什么生成、来自哪里、放在哪里以及验证是否通过。

**经验：** 高质量论文图片的核心不是“看起来像AI做得很漂亮”，而是视觉层级清楚且每个
像素都能追溯到真实模型、数据或明确标注的示意关系。

## 16. 主模型确认与全文定位是最优先的人机协作点

只做自动检索和质量评分仍可能出现两个高代价问题：AI沿错误路线继续完成全部代码和论文；
文献虽然真实存在，但精确公式或参数只根据摘要、二手引用或记忆写入。

因此新增：

1. Stage 3候选矩阵完成后生成 `model_route_checkpoint.md`，主动汇报题目理解、数据条件、
   检索词、文献链接、候选模型、推荐/否决理由、创新、求解、验证和风险；
2. 用户明确批准前，`human_model_checkpoint.status=pending`，不得锁定模型、进入主体求解
   或开始论文正文；
3. 新文献或附件足以改变路线时重新确认，不重复询问不影响模型的文字和排版修改；
4. 核心文献按用户PDF、开放出版商、arXiv/PMC/机构库/官方标准的顺序合法获取；
5. 记录PDF页序号、印刷页码、章节、公式/表格/图号、本地路径、来源地址和SHA-256；
6. 扫描PDF或公式抽取失败时渲染页面视觉核验；
7. 付费墙全文不绕过权限，向用户索取；只有摘要时降低主张强度；
8. 没有全文定位的精确公式、参数和定量结论不得进入终稿。

**经验：** 最重要的人工确认不是在论文写完后挑措辞，而是在模型路线即将锁定时阻止错误
方向；最重要的文献核验不是确认DOI存在，而是确认原文具体位置、条件和论文主张真正一致。

## 17. 保留质量标准，增加中央执行骨架

与外部工程化Skill比较后，决定只学习执行系统，不降低本地文献、模型、稳健性、图表和
终稿门禁：

1. 新增`assets/workflow_manifest.json`，统一10阶段顺序、完成检查、产物契约和改动影响；
2. `decision_log.json`继续记录“为什么”，manifest记录“执行什么、何时重跑”；
3. 新增`workflow_manager.py`，支持状态、阶段验证、checkpoint和最小重跑计划；
4. 数据、文献、模型代码、结果、图表、论文和提交文件分别映射到受影响阶段；
5. 新增`build_code_manifest.py`，自动生成代码清单和Markdown代码附录；
6. 代码清单记录入口、用途、依赖、引用产物、大小和SHA-256；
7. 默认不把全部源码塞入论文，只有明确要求时使用`--include-source`；
8. `doctor.py`同步检查manifest、执行脚本和decision-log v3.2。

**经验：** 对质量优先型工作流，正确方向不是删门禁换速度，而是把阶段依赖、重跑范围和
代码附录自动化，让同样严格的标准执行得更稳定、更少遗漏、更少重复。

## 18. 第二类改稿链：方法错误而非写作错误（2023 CUMCM A 题，11 轮外部审查）

前 17 节记录的是**写作、图表、文献、结构**类改稿。本节记录一条性质不同的改稿链：
论文的写作与图表始终没有大问题，**十一轮改动几乎全部发生在求解方法层面**，
且其中两轮直接改变了最终交付的设计参数。

这类改稿的特征是：**每一轮改动前，所有自检都是通过的。** 收敛曲线漂亮、断言全过、
不动点已收敛、极限对拍无误——错误藏在"检验的口径"和"宣称的强度"里，而不是代码里。

### 18.1 改动了什么

| 轮次 | 触发 | 后果 |
|---|---|---|
| 2–3 | 密度贪心在成本不等时被当成精确最优；耦合目标只做单轮取舍 | 交付结果变更（Q3） |
| 4–5 | "精确最优"越档宣称；交换判据把整数删除量当连续可分 | 措辞分三档 + 新增邻域检验 |
| 6 | 全部验证都是内部自洽检验 | 补独立方法对拍，发现 `10⁻³` 量级系统正偏 |
| 7 | 敏感性用自制分箱探针 | 跨方案结论**符号反转**（−0.903% → +0.567%） |
| 10 | 粗档筛选结论未在交付档位复核 | 两个"更优"方案在交付档位均不可行 |
| 11 | 网格细化中心未跟随最优；基线欠优化；代理口径被搜索破坏 | **Q2 与 Q3 交付结果均变更** |

第 11 轮最能说明问题：Q3 相对 Q2 的优势从 +0.567% 缩到 +0.134%，
**不是因为 Q3 变差（它涨了 0.42%），而是因为基线 Q2 涨得更多（0.86%）**。
基线没优化到位时，改进量会被系统性高估——这条已单独固化为反模式 D10。

### 18.2 为什么这类错误躲得过所有自检

一句话：**算法自检在题意读错或代理口径错时全都会通过，因为内核是自洽的，
只是自洽在错的问题上。**

因此本次新增了一道**非算法性**检查：最终公式里出现的每个符号与常数逐条追回题面原文。
本项目 12 项全部对上，但这道检查的价值不在"发现了错"，而在它是唯一**不依赖代码正确性**
的检查——其余检验全都建立在"题意读对了"这个未经检验的前提上。

### 18.3 一条独立于本题的经验

决策变量审计（`SEARCHED / FIXED_BY_PROOF / FIXED_BY_HEURISTIC / GIVEN` 四态登记 +
对每个 `FIXED_BY_HEURISTIC` 做反方向探针）在本项目跑出四项探针，**全部确认原取值最优，
但其中两项的原理由是错的**。

这比"发现取值错了"更值得记录：**取值对不等于理由对，而错的理由会在条件变化时把结论带偏。**
本项目中，"抬高安装高度会加重挡光"这句话对**均匀抬高**成立、对**梯度抬高**不成立
——把一个关于梯度的问题当成关于水平的问题回答，直接导致另一个子问题漏掉了整个自由度
（该自由度实测值 +1.97%）。

### 18.4 沉淀位置

方法类门禁全部写入 `references/optimization_search_rigor.md`（16 条 + 案例索引 C1–C16），
由 `stage_05_subproblem_loop.md` §C.1 触发，反模式编号 D6–D13。
本节只保留"这条改稿链长什么样"，不重复门禁细节。

### 18.5 十一轮之后，第二次独立审查又发现了一条更上游的问题

第 11 轮结束、交付包已冻结后，用户找了另一个模型做独立复核。它没有重复前 11 轮已经修过的
问题，而是发现了一条**更上游**的：论文把题面原始目标 `max E/A` 重述为 `min A s.t. E≥E0`，
理由是"约束在最优处必然取等，因此二者等价"——这条推理本身不成立（离散、多档成本时两者
一般选出不同集合），而且**连暴力穷举对拍的 oracle 也继续优化被替换后的目标**，导致"与暴力
穷举逐位相同"这条验证只证明了代理目标求对了，不能证明原目标求对了。

复核时用贴近本题实例参数（两档面积、每档数百至上千单元、`g` 连续分布）的合成数据做数值对拍，
400 组算例中两个目标从未分离——说明本题这个实例大概率安全，但"精确最优"这个措辞在补上
这道针对真实候选集的对拍之前，**没有资格这么说**。已固化为 §1.5（目标函数台账）与反模式 D13。

**这条经验比它修复的具体问题更重要**：十一轮内部审查全部聚焦在"取舍算法、交换判据、
代理口径"这些**给定目标之后**的执行细节上，没有一轮往回检查"目标本身是不是被换过"。
决策变量会被静默消元（§2），**目标函数同样会被静默重述**，而且重述之后的全部下游验证
（精确性分档、暴力对拍、交换证书）都会显得天衣无缝——因为它们确实解对了那个换过的问题。
独立的第二次审查之所以能看见这条，正是因为它不共享前 11 轮已经收敛到的框架。

**经验：** 交付包里附一份 `CHANGELOG.md`（"旧版的问题 → 新版做法 → 验证数据"三段式）
不只是给评审看的诚信材料，它是**唯一能让方法类教训在项目结束后仍可复用**的载体。
最终 PDF 只记录最后一版是什么，记录不了为什么前十版不对。旧日志保留并附事后更正、
不回改，同理。
